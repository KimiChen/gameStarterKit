# 额外功能说明

## 1. 定位

gameStarterKit 的核心定位仍是游戏开发基础框架。除核心客户端、服务端、共享契约和本地开发工具外，仓库中
还可能提供一些面向特定项目或场景的额外功能、兼容代码和参考实现。

这些额外功能：

- 不属于核心框架的能力承诺、稳定性承诺或长期维护承诺；
- 不作为项目架构、代码组织、验收标准或后续演进的强制约束；
- 不保证完整覆盖所有平台、服务商、环境或业务流程；
- 可能根据实际开发需求增加、调整、替换、停用或移除；
- 使用前需要由采用方自行评估适用性，并完成目标环境所需的配置、测试和验证。

额外功能的存在不表示核心框架必须依赖或启用它；额外功能暂缺、未完成或发生变化，也不影响核心框架本身的
定位和完成标准。

## 2. 额外功能类别

项目可能提供但不作承诺、也不作为项目约束的额外功能包括：

- 生产部署、持续交付、线上伸缩、监控告警、备份恢复等生产运行体系。
- 充值、支付、订单、退款、对账等商业化能力。
- 微信、抖音等渠道的账号、登录、支付、广告、分享及 SDK/API 接入。
- 渠道打包、审核、灰度、热更新、合规、商店发行及运营能力。

上述列表用于归类额外能力，不代表仓库当前已经完整实现每一项，也不构成未来必须实现或持续维护的路线图。

## 3. 当前仓库中的相关实现

当前代码中可以看到以下额外功能或基础实现：

### 3.1 渠道兼容与登录

- `apps/client/src/core/wechat-compat.ts` 提供微信小游戏环境兼容处理，并由 `Main.ts` 接入。
- `apps/client/src/net/http/account.ts` 提供 `wxLogin` 请求封装。
- 外部身份契约可能包含本地开发示例之外的渠道接口。

这些代码属于可选的渠道扩展，不改变客户端通用网络、View/Logic 或玩法框架的核心约束。

### 3.2 支付与购买

- `apps/server/src/http/pay/wxNotify.ts` 提供微信支付通知入口。
- `apps/server/src/core/economy/purchases.ts`、充值 SKU、`PAY_ENABLED`、purchase 常量和 MySQL
  `purchases` 表构成购买流程的参考实现。
- 游戏内软货币商店、资产 effect 和 outbox 同时服务于玩法数据一致性，可独立于真实货币支付使用。

上述支付和购买代码按额外功能管理，不代表其业务完整性、安全性、合规性或目标环境可用性已经得到保证。

### 3.3 辅助后台组件

仓库还包含 monitor、consumer、repair worker 等辅助组件，用于展示或验证本地开发中的后台处理方式。
它们是否随默认开发进程启动、是否继续维护以及采用何种实现，可根据实际项目需要调整，不构成核心框架约束。

## 4. 使用原则

1. 核心框架不得因为某项额外功能不存在而无法进行常规玩法开发和本地验证。
2. 额外功能可以复用 shared、网络、数据一致性和本地测试基础，但不应反向改变这些核心模块的通用契约。
3. 采用额外功能时，应由实际项目补齐所需配置、错误处理、安全校验和场景测试。
4. 文档或代码中出现某项额外功能，只表示仓库提供了相关实现或参考，不表示对完整性和后续维护作出承诺。
