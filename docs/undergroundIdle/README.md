# 《Underground Idle》策划案

> 文档版本：0.1（方案草案）  
> 编写日期：2026-08-28  
> 目标工程：gonoGame 开发期框架  
> 核心网络模型：Lobby WS-RPC  
> 文档目的：定义可制作、可测试、可逐步扩展的挂机玩法 Demo；本文档集不是线上运营、商业化或生产部署承诺。

## 策划摘要

玩家经营一座位于地下矿城的矿业公会：安排矿工在矿井与升降机岗位工作，定期收取矿石、升级设施，或派遣
矿工探索废弃坑道和古代遗迹。核心选择来自三处：升级哪一段生产链、派谁去远征、选择多长的远征。

本玩法用于演示框架的 WS-RPC 能力，与多人 Room Demo 分工明确：

- 不创建玩法 Room，不用 Schema 持续同步；
- 服务端不启动玩家级逐秒 Timer；
- 客户端增长动画和倒计时只是表现；
- 权威结果在快照、收取、升级、调岗、派遣和领取等 RPC 边界按服务端时间计算；
- 写操作通过状态版本、payload 绑定和领域收据处理并发、重试、超时与掉线；
- 首版状态与模式内资源留在 durable Redis 玩家热档，不强行引入跨 MySQL/Redis 经济。

这里的“公会”是世界观中的玩家个人经营组织，不是现有多人社交 `guild`。技术领域统一建议使用 `idle.*`。

## 已确定的首版取舍

| 议题 | 首版决定 |
| --- | --- |
| 网络模型 | 只使用 Lobby WS-RPC，不使用玩法 Room |
| 生产计算 | 检查点 + 服务端时间离散结算，最多计算 8 小时 |
| 生产链 | 矿井开采、升降机运输、仓库容量三段瓶颈 |
| 矿工 | 4 名固定角色、两类岗位、无抽卡/等级/装备 |
| 远征 | 单槽、三个地点、C/B/A/S 保底结果，不做实时战斗 |
| 归队 | 到达 `endAt` 自动回原岗位，和奖励领取解耦 |
| 经济 | 模式内矿石、碎片、行动力和一次性通关徽记，不接充值货币 |
| 随机 | 出发时按配置版本固化私有结果，领取不重抽 |
| 持久化 | durable Redis 玩家热档中的有界版本化领域聚合 |
| 一致性 | per-user 锁/fence、领域版本、payload 绑定、有限期操作收据 |
| 推送 | 首版不需要；快照是唯一自愈入口 |
| 长期系统 | 每日委托、研究、遗物、负伤、多队均后置 |
