# 《Underground Idle》产品定位与核心玩法

> [返回总目录](README.md) · [下一篇：经济、矿场与建筑](02-economy-and-mine.md)

## 1. 项目概述

### 1.1 一句话介绍

玩家经营一座位于地下矿城的矿业公会：安排矿工在矿井与升降机岗位工作，定期收取矿石、升级生产设施，
或派遣矿工探索废弃坑道和古代遗迹，通过“稳定生产”与“高价值远征”之间的取舍逐步深入地下世界。

### 1.2 产品定位

《Underground Idle》是一个竖屏、轻量、单玩家异步挂机玩法，主要承担本框架的 WS-RPC 能力演示：

- 请求—响应式玩法命令，而不是实时 Room 状态同步；
- 服务端权威时间与离线收益；
- 玩家级串行写、状态版本、重试和幂等；
- 建筑升级、矿工调岗、远征派遣和奖励领取的一致性；
- 体力、版本化配置和确定性随机的首个实际玩法接入；
- 断线、切后台、切设备后通过完整快照恢复界面。

这里的“公会”是世界观中的**玩家个人经营组织**，不是现有 `guild.*` 多人社交公会。实现时建议使用
`undergroundIdle.*` 作为 RPC 与代码领域名。它同时避免两重混淆：与现有 `guildId`、工会事件及社交接口的
**世界观**混淆；以及与仓内既有 Room 玩法 `idle`（`GameplayModeId.Idle`，一个 gameplay module）的**实体**
混淆——后者按 [Non-intrusive.md](../Non-intrusive.md) §3.1 与本 feature 是两类不同实体，⛔ 不得同名。

### 1.3 目标平台与体验节奏

| 项目 | 目标 |
| --- | --- |
| 客户端 | Cocos Creator 3.8.8，750×1624 竖屏设计分辨率 |
| 单次主动操作 | 30 秒～3 分钟 |
| 短期回访 | 1～20 分钟，适合开发现场演示完整闭环 |
| 离线回访 | 1～8 小时 |
| 首版阶段目标 | 公会大厅达到 3 级，首次完成古代遗迹并领取深层开拓徽记 |
| 首版内容寿命 | 以验证框架和玩法闭环为主，不追求无限成长 |

### 1.4 明确不做什么

首版不创建玩法 Room，不使用 Colyseus Schema 持续同步，也不为每位玩家启动逐秒 Timer。客户端看到的矿石
数字增长、体力倒计时和远征倒计时都是本地表现；权威结算只在进入页面、收取、升级、调岗、派遣、领取等
RPC 边界按服务端时间完成。

首版还明确排除：

- 实时或手动远征战斗；
- 抽卡、矿工品质、随机成长和复杂装备；
- 永久死亡、装备损坏和远征中途取消；
- 多队并行、任务队列和多人协作远征；
- 排行榜、交易、拍卖、付费加速、广告倍率；
- 转生、无限等级和指数复利系统；
- 现有 MySQL 货币、充值或背包道具的跨存储发奖；
- 生产部署、灾备、线上扩缩容、运营后台与告警体系。

## 2. 设计目标与原则

### 2.1 四个设计支柱

1. **回来总有收获**

   矿场持续积累，远征提供保底奖励。玩家可以因容量和时间上限损失“潜在收益”，但不会因为一次随机失败
   丢掉已有资产或长时间完全空手。

2. **选择必须可解释**

   界面明确展示当前生产瓶颈、派走矿工后的产率变化、远征推荐能力、结果范围和归队时间，不依赖隐藏规则
   制造选择。

3. **离线结果必须可重算、可恢复**

   服务端保存检查点和有界状态，不逐秒模拟。相同状态、配置版本、服务端时间和随机种子必须得到相同结果。

4. **Demo 范围小，但正确性完整**

   用少量建筑、固定矿工和一个远征槽证明 WS-RPC、幂等、版本、持久化和客户端恢复，不用堆内容掩盖数据
   边界问题。

### 2.2 玩家核心决策

玩家主要面对三类决策：

- **升级哪一段生产链**：矿井、升降机和仓库互相制约，只升级一条会很快遇到瓶颈。
- **派谁去远征**：优秀岗位矿工离开后会降低产量；远征专精矿工的机会成本较小，但某些任务需要更多人。
- **选择多长的远征**：短任务快速回收，长任务占用槽位更久，但行动力效率、综合收益和阶段奖励更好。

废弃坑道第一次派遣故意允许使用空闲的伊芙，以便低门槛完成教学。大厅升到 2 级前要求三座生产建筑达到
2 级，届时四名矿工可填满四个岗位；菌光洞窟及古代遗迹才正式产生可见的生产机会成本。

## 3. 世界观与美术方向

### 3.1 世界设定

地表资源枯竭后，人们重新启用一座废弃的垂直矿城。玩家继承最上层的一间破旧公会大厅，依靠几名矿工、
一座老矿井和一台生锈升降机恢复生产。随着大厅和生产设施修复，玩家会发现菌光洞窟、失落机械库以及
更深处的古代文明遗迹。

世界观服务于系统表达：

- 矿井和升降机对应生产链的两段瓶颈；
- 仓库解释离线容量上限；
- 公会大厅解释矿工数量和内容解锁；
- 远征解释稀有资源、体力消耗和确定性奖励；
- 大厅等级与矿层深度解释长期进度，但首版不做无限地图。

### 3.2 视觉关键词

- 温暖灯火与幽暗矿层的冷暖对比；
- 木质脚手架、黄铜机械、轨道矿车和巨型升降机；
- 轻冒险而非恐怖，矿工受伤和失败不做残酷表达；
- 主界面用纵向矿井剖面展示“向下深入”；
- 数值和状态优先清晰，动画不遮挡瓶颈、容量、倒计时等信息。

## 4. 核心循环与成长节奏

### 4.1 分钟级循环

```text
查看矿场状态
  → 收取仓库矿石
  → 查看当前生产瓶颈
  → 升级矿井、升降机或仓库
  → 调整岗位
  → 等待下一次收取
```

### 4.2 十分钟级循环

```text
选择远征地点
  → 选择矿工
  → 比较奖励与矿场产率损失
  → 消耗行动力并出发
  → 到期后矿工自动归队
  → 领取已固化的远征奖励
```

### 4.3 长期循环

```text
积累矿石与遗迹碎片
  → 升级公会大厅
  → 解锁固定矿工和更深远征
  → 优化生产岗位与远征队伍
  → 首次完成古代遗迹并领取“深层开拓徽记”
```

### 4.4 单次登录推荐流程

1. 进入页面，拉取完整快照。
2. 若离开超过 60 秒且产生收益，展示离线摘要。
3. 收取仓库矿石。
4. 领取已完成远征。
5. 判断矿井或升降机瓶颈，选择一次升级或调岗。
6. 派遣下一支远征。
7. 离开页面；生产与远征继续按时间戳推进。

## 5. 功能范围

### 5.1 首版必须具备

| 编号 | 功能 | 首版验收重点 |
| --- | --- | --- |
| IDLE-01 | 玩法激活与完整快照 | 首次激活只建档一次，老玩家状态可恢复 |
| IDLE-02 | 权威离线生产 | 不依赖玩家级 Timer，容量和 8 小时上限正确 |
| IDLE-03 | 仓库收取 | 重复请求不重复入账 |
| IDLE-04 | 矿井、升降机、仓库升级 | 先按旧参数结算，再扣费升级 |
| IDLE-05 | 公会大厅升级 | 解锁固定矿工与远征地点 |
| IDLE-06 | 矿工岗位分配 | 一人一状态，调岗前按旧阵容结算 |
| IDLE-07 | 行动力恢复与消耗 | 只使用服务端时间，失败不扣体力 |
| IDLE-08 | 单远征槽 | 出发、计时、自动归队、待领取、领取闭环 |
| IDLE-09 | 确定性远征奖励 | 出发时固化，领取不重新抽取 |
| IDLE-10 | 离线回归摘要 | 展示收益、满仓损失和归队信息；第二阶段可增加伤愈 |
| IDLE-11 | WS-RPC 结果恢复 | 超时和掉线后使用相同请求 ID 或完整快照确认 |
| IDLE-12 | 客户端页面生命周期 | 页面关闭后迟到结果不更新旧 View |

### 5.2 第二阶段候选

- UTC+8 每日委托板；
- 矿工等级、固定成长曲线和有限特质；
- 远征负伤与休养；
- 研究室及有限永久加成；
- 遗物收藏和单槽装备；
- 第二远征槽；
- 只携带 `stateVersion` 的尽力唤醒推送；
- 远征事件日志和多段式“继续深入/安全返回”选择。
