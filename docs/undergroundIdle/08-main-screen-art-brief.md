## 1. 文档目的与真相优先级

本文把拟定的主界面方向转换为可执行的首次美术任务，避免效果图完成后仍需猜测状态、热区、拆层和运行时
数据。效果图、状态板、工程资产和 UndergroundIdleMain 装配都属于后续交付；只有依次通过本文的视觉审稿门、FairyGUI
装配检查与 Creator 真实预览，才可把对应结果登记为实现。

本文不是新的玩法系统，也不改变服务端权威边界。出现冲突时按以下顺序处理：

1. 数值、解锁、角色状态和 RPC 行为以[经济、矿场与建筑](02-economy-and-mine.md)、
   [矿工、远征与新手流程](03-workers-and-expeditions.md)和
   [页面体验、客户端与 WS-RPC](04-client-and-rpc.md)为准；
2. 跨页面视觉语言、色板、资产规格和动效边界以[美术表现与资产制作](07-art-direction.md)为准；
3. 主界面拟定构图、效果图批次、分层和审稿口径以本文为准；
4. 概念图中没有业务定义的箱体数量、灯光亮度和装饰位置只作为构图参考，不反推玩法数值。

### 2.1 概念图的正确语义

- 三名主舞台角色分别对应铁镐·格伦、绳索·诺拉和提灯·伊芙；医师·奥托需要在 `FX-04` / `SPEC-04`
  建立米白制服、护目镜、医疗包与方形药箱基准，但大厅 1 级仍不出现在主舞台；
- 右下锁门表示更深层内容尚未开放，不表示大厅 1 级已经可用的“废弃坑道”被锁；
- 概念母版的建筑材质丰富度应接近“稳定”外观阶段，用于定义风格上限，不代表初始 1 级建筑外观；
- 顶部箱体数量和容量条填充只是概念构图，不代表仓库的权威库存；
- 四指标卡底部细条是状态轨，不是百分比进度条；
- 空白文字槽是有意保留的运行时文本空间，不得交给生成图片补伪中文。

### 3.1 固定区、舞台视口与热区

- 标题、资源栏、仓库条、四指标卡和底栏固定；首版不随建筑升级、深层解锁或角色离岗移动；
- 中央矿井是固定裁切视口，不提供自由滚动。场景可以做轻微视差、升降机位移和矿车固定路径，不改变热区；
- 设计稿以 750×1624 审阅，建议使用 1500×3248 的 2×分层源稿；安全区使用单独参考线，不画进背景；
- 图标可小于触控区，但主要按钮和图标按钮的标注热区不得小于 88×88 设计像素；
- 黄色收取按钮的完整矩形都是点击区，矿车图标只是语义图标；
- 矿井热区固定在上层凿岩区，升降机热区固定在右侧绞盘与笼体，仓库热区覆盖容量条，公会大厅入口使用
  左上徽章；装饰物不单独抢占点击；
- 角色、矿车和灯光可以越过场景层内部遮挡，但不得盖住仓库按钮、指标文字或底栏角标。

### 3.2 首页远征摘要

主页不增加独立远征卡，状态收口到底栏远征页签：

| 远征状态 | 页签表现 | 场景表现 |
| --- | --- | --- |
| 空槽 | 地图/指南针图标，无角标 | 伊芙可以空闲驻留在矿井舞台 |
| 进行中 | 行走图标 + 短倒计时，如 `00:45` | 参与远征的矿工离开原岗位，空位保留岗位牌 |
| 已到 `endAt`、待领取 | 宝箱图标 + “待领取”角标，一次暖灯提示 | 矿工已经自动归队，不能继续表现为离岗 |
| 已领取 | 恢复空槽入口 | 归队位置保持，不播放第二次发奖反馈 |

短倒计时只是基于服务端时间的本地投影；美术不能用进度条或动画暗示客户端可以提前完成远征。

## 4. 分层源稿与文件约定

### 4.1 建议图层组

```text
00_GUIDE_SAFEAREA        安全区、裁切线、热区和标注；不导出
10_BG_ROCK               远景岩壁、深度渐变、低频纹理
20_STRUCTURE             洞口、木梁、轨道、固定管线
30_BUILDING              矿井、升降机、仓库、公会大厅入口及阶段附件
40_PROP_STATE            矿车、矿石堆、箱体填充、锁链、岗位牌
50_CHARACTER             格伦、诺拉、伊芙、奥托及拆件
60_LIGHT_FX              工作灯、冷光、尘埃、火花、收取/升级反馈
70_UI_COMPONENT          面板、按钮、图标、状态轨、页签、弹窗
80_RUNTIME_TEXT          中文、数字、角标、倒计时；效果图可见，资产导出时关闭
90_REVIEW_ANNOTATION     审稿说明、版本和差异标记；不导出
```

同一对象的默认、告警、锁定和升级阶段必须使用相同画布、锚点和占位框。状态稿只切换对应状态层，不重新生成
整张页面，避免人物、设备和组件在不同状态间漂移。

### 4.2 命名

- 效果图：`ug_fx_<page>_<state>_vNN.png`；
- 规范板：`ug_spec_<topic>_vNN.png`；
- 工程资产：继续使用 [07](07-art-direction.md) 规定的 `ug_` 前缀和资产类型命名；
- `vNN` 是审稿迭代号，不是玩法 `configVersion`；
- 已批准稿新增版本，不覆盖概念母版或上一个批准版本。

锁定“只增加附件、灯光与轮廓复杂度”的成长语言；板内和板底都明确标注它们不是 `ART-03` 切图源。工程交付
必须重新透明抠出、同画布归一、登记锚点、复核点击区并做 1×/溢出验证。两张规范板均为 2480×3508，引用图
位于独立层，所有可见说明位于 `90_REVIEW_ANNOTATION`。

### 8.3 `SPEC-05` UI 与网络状态

覆盖 LoadingSnapshot、Mutating、ResultUnknown、断线重连、资源不足、行动力不足、矿工忙碌、旧状态刷新和
禁用原因。`TIMEOUT`、`CONN_LOST` 和 `IN_PROGRESS` 不得表现成明确失败，也不能提供一个会换新请求 ID 的
“重新提交”按钮；优先文案为“正在确认操作结果”“请勿重复提交”“刷新状态”。

`v01` 首次制作需使用同一组件槽登记九态、状态入口、允许操作、明确禁止和 ResultUnknown 的
`queryOperation / getSnapshot` 安全路径。状态同时使用独立图标、外框形状、提示条、明确文案和按钮状态，
颜色只作辅码；文案中不得出现“重新提交”。拟定可编辑源为 `art/specs/ug_spec_ui_network_states_v01.svg`，运行时
示例文案与板外审稿说明分别位于 `80_RUNTIME_TEXT`、`90_REVIEW_ANNOTATION`。

## 10. 交付规格

- 全屏效果图审阅尺寸：750×1624 PNG；
- 建议分层源稿：1500×3248，sRGB，可编辑图层；
- 状态联系表：按内容使用 2048×2048 或多张 750×1624，不为塞进一张图而缩小到不可读；
- 图标：256×256 透明源图；常用显示尺寸 64～96 逻辑像素；
- 角色头像：512×512；场景小人：512×768 内；
- 远征插画：640×360，允许卡片裁切；
- PNG 使用干净透明边缘，带颜色外扩避免图集渗色；
- 所有源稿附版本、图层名、锚点、九宫格线和建议运行尺寸；
- 效果图允许显示评审文案，但 `80_RUNTIME_TEXT` 必须可以一键关闭；
- 禁止水印、商标、伪 UI、伪文字和来源不清的现成游戏资产。

## 11. 审稿门

### Gate A：P0 主界面语义

- `FX-01` 数值、岗位、建筑阶段和容量填充能由首版配置解释；
- 三秒内能找到收取、瓶颈和远征；
- `FX-02` 的 UI 与场景反馈表达同一状态，已满后没有继续生产动画；
- `SPEC-01` 标清安全区、固定区、热区、锚点和遮挡；
- `SPEC-02` 关闭文字后没有伪字、数字或不可拆的整页依赖。

Gate A 人工通过后才允许把主界面 `ART` 资产标记为视觉冻结版；基于可编辑分层源提前制作的工程验证包不等于
人工通过。

### Gate B：P1 主循环

- 矿工、远征、升级和离线弹窗沿用主界面组件语言；
- 编队确认先展示机会成本，再展示出发按钮；
- 远征中、自动归队和待领取能被区分；
- 结果等级同时使用字母、框形和材质，不只依赖颜色；
- 禁用、锁定、已满和待领取都有图标/形状与文字空间。

Gate B 人工通过后才允许把对应页面图集标记为最终验收版；试制资产只能用于工程装配验证和自动审计，仍需
人工视觉冻结。

### Gate C：工程交接

- 所有运行时中文、数字、等级、价格、倒计时和角标均未烘焙；
- 四角色在 64～96 像素下凭轮廓可区分；
- 四建筑三阶段不改变热区和岗位锚点；
- 关闭粒子、灯光呼吸和装饰动画后核心状态仍清楚；
- Creator 750×1624 真实预览通过安全区、长数字、满仓、锁定、离岗、断线和结果弹窗检查；
- 分层资产、九宫格、pivot 和透明边缘符合 `apps/art/fairygui` 的真源流程。

### 11.1 初始 Gate 状态

| Gate | 初始判定 | 关闭前必须完成 |
| --- | --- | --- |
| `Gate A` | `未开始` | 制作 FX-01/02、SPEC-01/02 与 1500×3248 真分层 Master；人工确认三秒扫描、角色身份、材质一致性和文字隔离 |
| `Gate B` | `未开始` | 制作 FX-03～09 的统一可编辑源与同构/差异证据；人工确认组件一致性、角色身份和信息扫描 |
| `Gate C` | `未开始` | 完成 ART 拆分、FairyGUI 首次装配与 Editor 单包发布、客户端绑定、稳定 `.meta`、自动门禁及 Dashboard/Creator 完整状态矩阵 |

只有对应交付真实产生并通过人工与运行时检查时才更新判定；不能用“PNG 看起来正确”代替分层、同构、Editor
发布或 Creator 验收。

### 11.2 首轮运行视觉验收包

完成首次 FairyGUI 装配并能在 Creator 打开 UndergroundIdleMain 后，提交以下可比较的差异包：

1. `VR-01 安全区与长数字`：同一运行版本导出 `0/0`、`88/68` 两组安全区，以及资源/仓库最大宽度；只检查
   文字基线、图标间距和底栏，不调整场景构图。
2. `VR-02 生产与仓库六态`：平衡、开采瓶颈、运输瓶颈、空仓、近满、满仓；每态同时截 UI 与场景，逐项标出
   矿堆、升降负荷、卸货和矿石飞入的开关。
3. `VR-03 远征闭环`：空槽、编队确认、进行中、到点自动归队、待领取、C/B/A/S 结果、首次深层徽记；使用
   同一角色身份和同一弹窗内容区，禁止通过换构图制造状态差异。
4. `VR-04 网络与资源异常`：Loading、Mutating、ResultUnknown、重连、状态冲突、余额不足、行动力不足、矿工
   忙碌；检查遮罩、H11 文案与按钮层级，不给 ResultUnknown 画成“失败”。
5. `MOTION-01 程序动效样张`：凿岩、升降笼、矿车、灯晕、尘埃、收取飞入、升级和解锁各提供正常/关闭两版；
   关闭后核心状态必须仍可辨，并登记持续时间、循环点、blend 与性能预算。

每个包必须附 750×1624 无标注运行截图、同尺寸标注图、变更说明和“禁止变化区”差异图。人工只审本包声明的
差异，避免把角色、材质、文案和交互同时改动后无法归因。

## 12. 明确不出图

- 实时战斗、自由移动地图、2.5D、等距视角和自由镜头；
- 经理、抽卡、商店、付费货币、广告和复杂倍率；
- 角色等级、装备、品质、皮肤和换装；
- 每日委托、研究、遗物装备、负伤、第二远征槽和多人协作；
- 昼夜、天气、全屏动态光照和复杂后处理；
- 任何把生成式整页图直接标记为工程资源的交付。

## 13. 推荐制作顺序

```text
UG-MAIN-CONCEPT-02 首次制作与审阅
  → FX-01～FX-09 + SPEC-01～SPEC-05 首次制作与人工签字
  → ART-01～ART-09 分层资产制作、manifest 登记与自动审计
  → FairyGUI 三页签首次装配、单包发布与客户端接线
  → Dashboard/Creator 首次基线预览
  → VR-01～VR-04 完整视觉状态矩阵验收
  → MOTION-01 程序动效、透明边缘与性能终检
```

每轮审稿只针对一个明确差异集，例如先统一“运输瓶颈的 UI + 场景联动”，再调整深层入口亮度，避免同时
改角色、构图、文案和材质造成无法判断的版本漂移。
