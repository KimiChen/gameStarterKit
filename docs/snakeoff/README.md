## 策划摘要

《Snake Off》是本项目拟用于替代 `ballMove` 默认演示入口的竖版实时对战玩法。玩家可以创建私人房间并取得一个保留前导零的六位数字码，也可以输入好友提供的六位码加入同一房间。每间房最多四名真人玩家，不要求四人坐满；当前在座成员全部进入 Ready 后，仍需由房主点击 Start，服务端复核条件并锁房后才开始。

战斗采用 750×1624 竖版表现：上方显示倒计时、房间或排名信息，中部为主战场，左下为方向摇杆，右下为加速按钮。客户端只上传方向、加速状态和递增序号；出生、移动、成长、食物、碰撞、死亡、得分与胜负均由服务端固定步长模拟决定。

首版定位是“开房链路的完整 Demo”，不是生产级通用房间平台。实时房间的低侵入式技术方案以
[邀请码房间与竖版贪吃蛇的低侵入式接入方案](../Non-intrusive-room.md) 为准；本目录负责产品、规则、竖版表现、
来源台账和验收口径。它需要证明以下闭环：

```text
创建房间 / 输入六位码
  → 1～4 个席位进入 Waiting
  → 当前成员逐个 Ready
  → 房主点击 Start
  → 服务端复核、锁房并开始竖版贪吃蛇
  → 结算
  → 首版返回已登录 Home
```

## 已确定的首版取舍

| 议题 | 已确定结论 |
| --- | --- |
| 屏幕方向 | 竖版，设计基线沿用本项目 750×1624 / `FIXED_WIDTH` |
| 房间入口 | 创建私人房间，或输入六位数字码加入 |
| 房间码 | 恰好六位十进制字符串；`012345` 不能被转成 `12345` |
| 房间容量 | 最多四名真人玩家 |
| 是否等满 | 不需要等齐四人 |
| Ready 条件 | 当前所有在座成员都必须 Ready，包含房主 |
| 开局动作 | 全员 Ready 后不自动开局；只有房主点击 Start 才触发 |
| 开局复核 | Start 前和所有异步边界后都要复核房主、精确成员集合、Ready、connected 与相应 revisions |
| 中途加入 | Playing 后锁房，不接受新成员 |
| 网络权威 | 客户端只发输入；服务端决定世界状态和结算 |
| 实现方式 | 面向本项目 TypeScript、Cocos Creator 3.8.8、FairyGUI 和 Colyseus 独立重写 |
| ballMove | Snake Off 验收后成为默认入口；首期先保留 ballMove 作为内部回归样例，不在同一阶段物理删除 |
| 路线仲裁 | 与 wsrpc/undergroundIdle 迁移入口路线相比，**Snake Off 优先**替代 ballMove 默认入口（2026-08-31 拍板） |
| 永久数据 | 首版不接经济、排行榜、赛季和永久战绩 |

## 待确认但不阻塞文档设计的产品项

下列规则没有从用户已确认条件中自动推导。文档给出建议基线，但实现前必须最终拍板：

| 编号 | 开放项 | 首版建议 |
| --- | --- | --- |
| SNAKE-OPEN-01 | 最少几人允许开始 | 建议 2 人；最终写入 `snake.private` profile 的 `startPolicy.minPlayers` |
| SNAKE-OPEN-02 | 单局结束方式 | 建议 90 秒限时计分；比“最后存活”更接近参考档案的短局节奏 |
| SNAKE-OPEN-03 | 死亡后是否复活 | 建议短延迟复活并保留分数；若采用淘汰制，需改结算和断线规则 |
| SNAKE-OPEN-04 | 真人蛇是否互撞 | 建议互撞；参考代码实际上只处理至少一方为 AI 的蛇碰撞，不能直接继承 |
| SNAKE-OPEN-05 | 房主在 Waiting 最终离开 | 建议转移给最早仍在房成员；成员各自 Ready 保留，但 owner/roster revision 变化会取消在途 Start |
| SNAKE-OPEN-06 | Playing 掉线 | 建议沿用现有 10 秒重连宽限，期间保持最后方向但停止加速；超时按死亡处理 |
| SNAKE-OPEN-07 | 等待房间有效期 | 分离短 lease TTL 与不可续的 Waiting deadline；开局释放本房邀请码映射，数字以后可被新房复用；首版结算后返回 Home |
| SNAKE-OPEN-08 | 邀请好友的首版含义 | 建议只提供复制六位码；渠道分享或好友系统后置 |

这些建议在后续章节均以“候选基线”标识，不能被当作已经确认的产品结论。

## 当前工程事实与方案目标

| 维度 | 当前已有 | 本方案拟建设 |
| --- | --- | --- |
| 玩法 | `ballMove` 与最小 `idle` mode | 新增 `snake` mode，并作为默认开房 Demo |
| 人数上限 | 当前 `MAX_PLAYERS = 4` | 复用数值 4；目标权威容量由 Snake manifest 生成，不继续依赖全局常量 |
| 开局 | 两人加入后自动开局 | 当前成员全 Ready 且房主点击 Start |
| 房间加入 | `joinOrCreate(RoomName.Game)` | `prepareCreate + create` 或 `resolve + joinById`，并使用一次性 access ticket |
| 房间码 | 无 | Redis 临时租约维护 `code → roomId`，六位码不充当内部 roomId |
| 模拟 | ballMove 20Hz 服务端 fixed-step | snake 复用 20Hz 房间 tick；客户端 60fps 插值 |
| 状态 | 每个 mode 有生成的 root Schema，但仍共用中央 manifest | 一次性改为 per-mode descriptor/codegen；Snake 摘要 root，蛇身和食物走有界世界快照 |
| 横向扩展 | 默认未启用 Redis Driver/Presence | 首版按单进程演示；多节点上线前另做协调验证 |
| 竖版 | 工程设计分辨率已是 750×1624 | 新建竖版房间页、HUD、摇杆与加速交互 |
