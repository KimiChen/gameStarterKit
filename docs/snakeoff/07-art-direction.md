# 07 · 竖版美术方向

> [返回总目录](README.md) · [上一篇：测试与实施路线](06-testing-and-roadmap.md) · [下一篇：来源与素材借鉴台账](08-source-and-asset-provenance.md)

> 美术状态：方向稿。文档编写时尚未从参考目录复制任何图片、音频、字体、动画、Prefab 或 UUID 元数据。

## 1. 视觉结论

Snake Off 的首版视觉目标是“清楚、轻快、适合四人短局的竖版竞技场”，而不是复刻《贪吃蛇大作战》的品牌、角色、皮肤或界面。

核心关键词：

- 竖向空间感。
- 高对比玩家识别。
- 圆润但不幼稚。
- 食物和掉落易读。
- Ready/房主/Start 状态一眼可辨。
- 战斗 HUD 克制，不遮挡蛇头。

## 2. 参考与原创边界

### 2.1 可以参考

- 左侧方向摇杆、右侧按住加速的双区交互。
- 创建、加入、房主标识和成员槽位的信息层级。
- 蛇头、身体节、普通食物、星形食物、掉落之间的视觉层级。
- 出生、加速、吃食物、死亡和排名变化需要明确反馈。

### 2.2 必须原创或重新设计

- 游戏名、Logo、字体组合、主色、背景纹样和按钮造型。
- 750×1624 竖版全部布局。
- 四人席位、六位码、Ready 和房主 Start 的状态组件。
- 蛇头/身体的最终造型、四名玩家色系和特效。
- 结算页、图标、音效和动效节奏。

### 2.3 未授权时不得使用

- 参考 remote bundle 的 PNG/音频/字体/动画。
- 参考 Prefab/import 的节点、UUID、切片和材质描述。
- 原游戏 Logo、角色、皮肤、文案、分享图和商业化素材。

精确看过的素材及其 native 路径登记在 [08](08-source-and-asset-provenance.md#4-素材借鉴登记)。“视觉参考”不等于“批准复制”。

## 3. 色彩与识别

### 3.1 场景色

建议使用深色、低饱和战场，让高饱和蛇和食物突出：

| 用途 | 候选色 | 说明 |
| --- | --- | --- |
| 页面底色 | `#11172B` | 深蓝黑，承接大厅与战斗 |
| 战场底色 | `#18223B` | 与页面形成层级 |
| 网格/纹理 | `#263554`，20%～35% alpha | 不干扰碰撞判断 |
| 主行动 | `#59D98E` | Ready/创建/确认 |
| 房主 Start | `#FFB84D` | 与 Ready 区分 |
| 危险/离线 | `#FF6678` | 错误、死亡、重连告警 |
| 主文字 | `#F4F7FF` | 高对比 |
| 次文字 | `#9EABC4` | 说明与禁用原因 |

色值是方向候选，最终要做 WCAG 对比检查和真机观感测试。

### 3.2 四名玩家

建议用色相、头部符号和轮廓三重区分，避免只靠颜色：

| 席位 | 主色候选 | 头部符号候选 |
| --- | --- | --- |
| P1 | 青绿 `#43D9B1` | 圆点 |
| P2 | 橙黄 `#FFB347` | 三角 |
| P3 | 蓝紫 `#7C8CFF` | 菱形 |
| P4 | 粉红 `#FF6FAE` | 十字 |

自己额外显示细白外轮廓或头顶箭头，不能只用“颜色更亮”表示。

## 4. 750×1624 页面线框

### 4.1 房间入口

```text
┌──────────────────────────┐ y=0
│ 安全区                    │
│          SNAKE OFF       │
│                          │
│      [ 创建房间 ]        │
│                          │
│      输入六位房间码       │
│   ┌─┬─┬─┬─┬─┬─┐          │
│   │0│1│2│3│4│5│          │
│   └─┴─┴─┴─┴─┴─┘          │
│      [ 加入房间 ]        │
│                          │
│      错误 / 加载状态      │
│                          │
│ [返回]                   │
└──────────────────────────┘ y=1624
```

六位数字使用等宽字体或固定格，不让 `1` 与 `8` 的宽度变化引起跳动。复制来的码仍显示为六格字符串。

### 4.2 Waiting

```text
┌──────────────────────────┐
│ 安全区          [退出]   │
│ 房间码  012345  [复制]   │
│ 当前 2 / 4               │
│                          │
│ ┌────────┐ ┌────────┐    │
│ │房主 P1 │ │ P2     │    │
│ │ 已准备 │ │ 已准备 │    │
│ └────────┘ └────────┘    │
│ ┌────────┐ ┌────────┐    │
│ │ 等待中 │ │ 等待中 │    │
│ └────────┘ └────────┘    │
│                          │
│ [准备/取消准备]           │
│ [房主开始]               │
│ 未满足时显示禁用原因       │
└──────────────────────────┘
```

- 房主标记靠近昵称，不用遮挡头像的大皇冠。
- Ready 用文字 + 图标 + 色彩，避免色盲误判。
- 空位不展示“邀请平台好友”承诺；可以显示“分享 6 位码邀请好友”。
- 非房主不显示 Start，或显示只读提示；不要放一个永远报错的主按钮。

### 4.3 战斗

```text
┌──────────────────────────┐ y=0
│ 安全区                    │
│ 01:12       排名/得分 1/4 │ 0..170 HUD
├──────────────────────────┤
│                          │
│                          │
│       竖版主战场          │
│     蛇 / 食物 / 掉落      │ 170..1420
│                          │
│                          │
│      自己头部不被HUD遮挡   │
│                          │
│  ┌──────┐        ┌─────┐ │
│  │ 摇杆 │        │加速 │ │ 1180..1540 overlay
│  └──────┘        └─────┘ │
├──────────────────────────┤
│ 底部安全区                │
└──────────────────────────┘ y=1624
```

摇杆和加速覆盖在战场下部，但背景半透明；它们的可触摸区域大于可见圆形。世界关键碰撞点不应长期被按钮遮住，出生与相机/场地取景要为底部控制区留余量。

### 4.4 结算

```text
┌──────────────────────────┐
│        本局结果           │
│                          │
│  1  P2   126 分           │
│  2  P1    98 分  ← 你     │
│  3  P4    74 分           │
│  4  P3    51 分           │
│                          │
│ 最大长度 / 死亡次数       │
│                          │
│       [返回主页]          │
└──────────────────────────┘
```

首版不显示段位、奖励、金币、“战绩已保存”或“再来一局”，避免超出真实数据与跨局房间语义。

## 5. 战场视觉

### 5.1 背景

- 使用原创可平铺的低对比网格/颗粒纹理。
- 地图边界比背景亮一档，危险时在蛇头靠近边界处加强提示。
- 不使用参考横版 `bg1` 直接裁切或旋转；其构图比例不适合竖版，权利状态也未确认。
- 场地四角可以用柔和装饰区分方位，但不能像可拾取物。

### 5.2 蛇

首版优先程序化/简单原创资产：

- 头部：一张可着色的圆润底图 + 眼睛/玩家符号。
- 身体：可批渲染圆节或沿曲线铺设的简单 sprite。
- 轮廓：自己有细外描边，出生保护有脉冲环。
- 长度增长：尾部平滑增加，不能单帧爆出大量节。
- 死亡：短暂缩放/溶解后生成掉落，避免复杂骨骼动画。

### 5.3 食物与掉落

| 对象 | 形状建议 | 动效 |
| --- | --- | --- |
| Dot | 小圆糖粒，2～3 种原创变体 | 轻微呼吸 |
| Star | 五角/晶体高价值物 | 慢旋转 + 光晕 |
| Wreck | 与所属蛇同色的小光点 | 先散开再稳定 |

食物的形状应在缩小到 24～40px 时仍清楚。不要把 UI 按钮颜色用于普通食物，避免误读。

## 6. HUD 与状态反馈

### 6.1 顶部 HUD

- 正中倒计时。
- 右上折叠四人排名或自己名次/分数。
- 左上网络状态只在重连/高延迟时出现。
- 房间码仅 Waiting 必须显示；Playing 中默认不占 HUD。

### 6.2 房间状态

- Ready：绿色勾 + “已准备”。
- 未 Ready：中性描边 + “未准备”。
- 房主：橙色小标签，不使用与 Ready 相同色。
- 重连中：席位变暗 + 环形进度/文字，不立刻显示空位。
- Start 进行中：整页轻遮罩与加载状态，但仍能接收权威回滚。

### 6.3 战斗状态

- 加速被服务端接受时，头部/身体出现方向拖尾；仅按钮按下不立即假定接受。
- 吃食物用局部缩放/粒子，不弹大数字遮挡战场。
- 出生保护用轮廓脉冲，不使用完全隐形。
- 重连时冻结/淡化输入层，显示“正在重连”，不让玩家误以为仍在控制。

## 7. 动效节奏

| 动效 | 候选时长 | 约束 |
| --- | ---: | --- |
| 页面淡入 | 160～220ms | 不阻塞网络状态更新 |
| 成员入座 | 180ms | 不重排时长过长 |
| Ready 切换 | 120～180ms | 权威 state 驱动 |
| 开局倒计时 | 3s | tick 驱动，不用本地计时决定开始 |
| 吃食物 | 80～140ms | 可批量，不制造对象风暴 |
| 死亡 | 300～500ms | 逻辑死亡即时，表现可延后结束 |
| 结算入场 | 250ms | 先停输入再显示 |

尊重 reduced motion/性能降级：粒子、拖尾和震屏可减少，但关键信息仍用形状和文字表达。

## 8. 首版资产清单

### 8.1 FairyGUI

- 通用 PrivateRoomLobby：Entry 背景、创建/加入按钮、六位输入格、错误状态，以及 Waiting 房间码、四席位、
  房主 tag、Ready/Start/退出状态；Snake contribution 只提供标题、图标和主题参数。
- SnakeResultView：四人排名 item、自己标记和返回 Home 按钮。
- 可复用按钮优先使用本仓已有 `Common_Btn`，但颜色/状态需检查契约。

### 8.2 Cocos 战斗

- 竖版战场平铺背景和边界。
- 一套可着色原创蛇头/身体基础图。
- 自己箭头、出生保护、加速拖尾、死亡效果。
- Dot、Star、Wreck 图形。
- 摇杆底、摇杆帽、加速按钮及按下态。
- HUD 字标、重连遮罩。
- 吃食、加速、碰撞、倒计时和结算音效；首版可使用明确授权的自有/开源素材。

## 9. 资源规格与命名

### 9.1 命名

新增资源统一使用 `snake_` 或目录 `snakeoff/`，例如：

```text
snake_bg_grid.png
snake_head_base.png
snake_body_base.png
snake_food_dot_01.png
snake_food_star.png
snake_wreck.png
snake_control_joystick_base.png
snake_control_joystick_knob.png
snake_control_boost.png
snake_fx_spawn.png
```

不沿用参考 bundle 的 UUID 文件名，也不把 `game_direction` 等源逻辑名冒充本项目原创命名。

### 9.2 图片

- 透明 PNG 使用紧边界，避免大面积空白。
- 圆形控制素材保持 1:1，不在 FIXED_WIDTH 下非等比拉伸。
- 可九宫的按钮在 FairyGUI/Cocos 导入设置中明确切片。
- 图集前保留可编辑原稿和导出规范；不要把参考 Cocos 2 atlas metadata 当真源。

### 9.3 音频

- 短反馈优先 wav/ogg 源稿，渠道格式在构建阶段转换。
- 同类高频吃食音效准备少量音高/变体，避免重复疲劳。
- 每个音频登记许可证或自制来源。

## 10. FairyGUI 与 Cocos 工作流

### 10.1 FairyGUI

```text
在 apps/art/fairygui 编辑器工程创建页面包
  → 750×1624 / MatchWidth 布局与 relation
  → 编辑器发布到 apps/Cocos/assets/resources/ui
  → Creator 生成 .meta
  → codegen View
  → gameplay/View contribution 进入 generated catalog
  → verify:fgui + Creator 预览
```

禁止手工编辑 FairyGUI XML。组件名、命名元素和包依赖是代码契约。

### 10.2 Cocos 战斗资源

- 原创战斗素材放入拟新增的 `apps/Cocos/assets/resources/snakeoff/`，或实现时最终确认的专用目录。
- 由 Creator 正常导入并生成 `.meta`。
- 逻辑代码真源仍在 `apps/client/src`，随后 `sync:client` 到 Cocos 壳。
- 不在 `apps/Cocos/assets/src` 手工创建 Snake 逻辑文件。

## 11. 参考素材若获授权后的流程

即使权利确认，也只能逐项处理：

1. 从 [08 台账](08-source-and-asset-provenance.md#4-素材借鉴登记) 找到精确 native PNG。
2. 记录 SHA-256、原 catalog 逻辑名、授权证据和批准人/日期。
3. 只复制实际像素源，不复制旧 Cocos import/UUID/Prefab metadata。
4. 按竖版、四人和本项目原创 UI 做必要重绘，不保留原品牌元素。
5. 在 Cocos 3.8.8/FairyGUI 重新导入，生成新 id、切片和 `.meta`。
6. 更新台账的目标路径、转换说明和实际复用状态。

未完成全部步骤时，状态保持“视觉参考/候选，未引入”。

## 12. 明确不做

- 不把横版截图直接旋转成背景。
- 不用原游戏 Logo、品牌、皮肤或分享图做“临时占位后忘记替换”。
- 不复制五席位房间 Prefab 再隐藏一个席位。
- 不在战斗阶段常驻大面积交互 FairyGUI 遮罩。
- 不用粒子和屏幕震动替代清晰的碰撞/Ready 状态。
- 不为首版制作复杂 Spine 蛇、皮肤商城和 UGC 主题选择。

## 13. 美术验收

- 750×1624、短屏、长屏、安全区布局不溢出。
- 四名玩家在色盲模拟和小屏下仍可区分。
- roomCode 六位均等显示，前导零清楚。
- Ready、房主、Start、重连四种状态不只靠颜色。
- 摇杆/加速的视觉和触摸区域匹配，多点触控可靠。
- 战场对象在最低目标分辨率下可读，不与 HUD/控制混淆。
- 所有提交素材均为原创或有台账中的明确授权。
- 参考目录中的 native/import/UUID 没有未经登记进入本仓。
- FairyGUI 设计源、发布物、契约和 Creator `.meta` 同步。
