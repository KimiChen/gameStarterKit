# 01 · 产品定位与核心循环

> [返回总目录](README.md) · [下一篇：房间与比赛流程](02-room-and-match-flow.md)

## 1. 项目概述

### 1.1 一句话介绍

一款最多四名真人通过六位数字码组局、全员准备后由房主手动开始的竖版实时贪吃蛇对战 Demo。

### 1.2 产品定位

Snake Off 首先承担“开房能力演示玩法”的角色：它应让开发者和体验者在一条可见、可解释的路径中验证创建、输码、入座、准备、房主开始、实时同步、结算和返回主页。

它不是简单地给 `ballMove` 换一套画面，也不是把参考档案整体搬进本项目。真正的产品价值来自两部分：

1. 房间行为清晰：六位码可口述、最多四人、不必坐满、全员准备但不自动开局。
2. 玩法反馈清晰：移动、吃食物、成长、加速、碰撞、死亡和排名都能在竖屏短局内被观察。

### 1.3 目标平台与节奏

| 项目 | 首版目标 |
| --- | --- |
| 设计分辨率 | 750×1624 竖版，`FIXED_WIDTH` |
| 输入 | 单指方向摇杆 + 独立加速按钮 |
| 对局人数 | 最多 4 名真人；最少开局人数待确认，建议 2 名 |
| 单局时长 | 待确认；候选基线 90 秒 |
| 服务端模拟 | 20Hz fixed-step |
| 客户端表现 | 60fps 渲染与插值，不改变权威结果 |
| 组局方式 | 私人房间码，不做公开匹配 |
| 断线恢复 | 沿用现有 10 秒重连宽限并增加 Snake 恢复语义 |

### 1.4 明确不做

首版不把以下内容带入开房 Demo：

- 公开匹配、排位、观战、跨区邀请和跨节点房间迁移。
- 平台好友列表、渠道分享 SDK、一键拉群或真实社交关系。
- AI 填充、五人房、主题选图、地图编辑或 UGC 发布。
- 皮肤、抽卡、商城、广告、道具、技能、赛季和排行榜。
- 永久战绩、经济奖励、体力扣除和结算发奖。
- 参考游戏的旧 Cocos 运行时、私有网络协议或微信平台能力。
- 在 Snake 验收前直接删除 ballMove 的代码和回归样例。

## 2. 设计目标

### 2.1 设计支柱

#### 支柱 A：三步内完成组局

房主从 Home 进入后，选择“创建房间”即可得到六位码；加入者进入同一入口，输入六位码后看到等待房。错误码、过期码、满房和已开局都返回稳定、可理解的结果，绝不能误创建另一个新房。

#### 支柱 B：Ready 与 Start 表达两层同意

Ready 表示“我已经准备开始”；Start 表示“房主确认以当前权威 roster 现在开始”。因此：

- 所有人 Ready 只让 Start 变为可用，不自动开局。
- 新人加入时只让新人默认未 Ready；成员最终离开或房主转移也保留其他成员 Ready。
- roster/ready/connection/owner revision 的任何变化都会让在途 Start 失效，房主必须按最新状态重新点击。
- 任一成员取消 Ready，Start 立即失效。
- 离线但仍在重连宽限的席位保留 Ready，却会阻止 Start。
- 客户端按钮状态只是提示，服务端必须重新验证。

#### 支柱 C：服务端结果唯一

客户端上传的是意图而不是事实。客户端不得上传坐标、蛇长、食物归属、碰撞结论、得分或赢家。相同 seed、初始成员和输入序列必须得到相同服务端结果。

#### 支柱 D：竖屏优先而非横版裁切

竖版不是把参考游戏横屏画面旋转 90 度。战场、出生分布、镜头、HUD、摇杆、加速键和触摸安全区都按 750×1624 重新设计；参考目录中的横版数值和素材只作为分析输入。

#### 支柱 E：短局中持续有反馈

玩家应在进入 Playing 后数秒内吃到第一份食物，并能很快理解“成长”和“加速有代价”。比分或长度变化、碰撞反馈、死亡与复活/淘汰、最终排名应有清晰表现。

### 2.2 玩家关键决策

首版只保留能直接形成对局决策的动作：

- 在 Waiting 中决定是否 Ready，以及房主何时 Start。
- 在 Playing 中决定移动方向。
- 决定何时加速追击、逃离或抢食，以及是否承担长度消耗。
- 决定走安全路线还是接近其他蛇争夺掉落。

所有不会改善上述闭环的系统都后置。

## 3. 核心循环

### 3.1 房主流程

```text
Home
  → 打开 Snake Off 入口
  → 创建房间
  → 获得六位数字码
  → 复制/口述数字码给好友
  → 等待 1～3 名好友加入
  → 自己与当前成员全部 Ready
  → 点击 Start
  → 进入 Playing
  → 结算后返回已登录 Home
```

### 3.2 加入者流程

```text
Home
  → 打开 Snake Off 入口
  → 输入六位数字码
  → 服务端解析并校验房间
  → 加入 Waiting
  → 确认成员后 Ready
  → 等待房主 Start
  → 进入 Playing
  → 结算后返回已登录 Home
```

### 3.3 单局战斗循环

```text
出生并获得短暂保护
  → 转向寻找普通食物
  → 蛇身增长、得分提升
  → 在安全移动与加速消耗间取舍
  → 与墙、自己或其他蛇发生空间关系
  → 死亡掉落并复活，或按最终规则淘汰
  → 时间/胜负条件满足
  → 服务端冻结结果并进入 Settle
```

### 3.4 结算退出

首版在结算确认后执行通用退出路径：停止 gameplay、释放精确 room ownership，并恢复到已登录 Home。这样不必在
第一阶段同时定义“原码是否重开、成员如何重新 Ready、掉线席位是否保留、第二局 match generation 如何隔离”等
另一套生命周期。

“再来一局”可作为第二阶段能力；届时必须把新一轮 roster/Ready、roomCode、access ticket 和 SnakeWorld reset
定义成完整事务，不能直接复用未清空的 Settle 状态。

## 4. 体验节奏

### 4.1 首次 30 秒

- 创建者立即看到六位码、复制入口、房主席位和自己的 Ready 按钮。
- 加入者输入满六位后才允许提交；错误不能清空输入，便于修正。
- 成员变化有明确提示，Ready 和 Start 的禁用原因可见。
- 开局后 3 秒内完成倒计时、出生和控制提示。

### 4.2 单局中段

- 普通食物维持稳定成长节奏。
- 加速会带来可见速度提升和长度/掉落代价。
- 排名只展示四人，信息量有界。
- 远端蛇通过插值平滑显示，本地蛇可做仅用于表现的轻量预测。

### 4.3 单局末段

- 最后 10 秒加强倒计时反馈。
- 服务端到达结束 tick 后拒绝后续移动输入的玩法副作用。
- 结算展示名次、得分、最大长度等临时数据，不伪装成永久战绩；确认后返回已登录 Home。

## 5. 与参考玩法的关系

### 5.1 借鉴的玩法思想

参考目录中以下思想适合被独立重写：

- 用有界循环队列维护蛇身点，并通过尾点移到头部推进路径。
- 按蛇长计算有效身体点数量。
- 用空间网格减少蛇身、食物和掉落的碰撞候选。
- 把方向和加速视为每帧输入，而不是客户端直接提交坐标。
- 用权威快照支持掉线恢复，并拒绝迟到旧快照覆盖新状态。
- 把普通食物、星形食物和死亡掉落区分为不同价值来源。

精确文件见 [来源台账](08-source-and-asset-provenance.md#3-代码借鉴登记)。

### 5.2 必须改造的差异

| 参考档案行为 | Snake Off 目标 |
| --- | --- |
| 横屏地图与横版 HUD | 750×1624 竖版重新布局 |
| UGC 房显示五个席位 | 最多四名真人 |
| 房间输入上限可见为八位 | 恰好六位数字码 |
| 平台分享 query 和私有后端 | 本项目 Lobby RPC + Colyseus GameRoom |
| 多处支持中途加入/离开 | Playing 后锁房 |
| AI、真人混合碰撞条件 | 真人碰撞规则由本项目明确决定 |
| 旧客户端锁步模拟 | 服务端权威 20Hz + 客户端插值 |
| 多种商业化和玩法分支 | 只保留核心蛇对战闭环 |

## 6. 首版范围

### 6.1 必须交付

- 创建私人房并返回六位数字码。
- 输入正确数字码加入同区、同玩法的 Waiting 房间。
- 最多四人，第五人无法入座。
- 当前成员全部 Ready，但不会自动开始。
- 只有当前房主能点击 Start；服务端并发复核成功后只开始一次。
- Playing 后锁房，Start 过程中阵容或 Ready 改变会取消本次开局。
- 竖版蛇移动、成长、加速、食物、碰撞、死亡和结算的服务端权威闭环。
- 通用私人房 Lobby、HUD、摇杆、加速和结算页。
- 断线重连、过期码、满房、已开局、非房主 Start 等异常路径。
- 来源与素材台账、纯规则测试、协议测试和 Creator 真实预览验收。

### 6.2 第二阶段候选

- 房间码分享卡片和渠道拉起。
- 结算后同房再来一局。
- 多张竖版地图或主题色。
- 自定义局长、淘汰制、复活制等房规。
- 观战、AI 补位、公开匹配。
- Snake 专用回放证据和永久战绩。
- 多节点 Redis Driver/Presence 与跨节点房间码解析。

### 6.3 成功标准

体验者不阅读开发文档，也能完成：

1. 一人创建房间并说出六位码。
2. 另一人输入该码加入。
3. 两人都 Ready 后，观察到对局仍未自动开始。
4. 非房主无法开始，房主点击后双方进入同一局。
5. 双方看到一致的主要结果并完成结算。
