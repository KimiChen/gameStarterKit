# 03 · 蛇规则与数值基线

> [返回总目录](README.md) · [上一篇：房间与比赛流程](02-room-and-match-flow.md) · [下一篇：客户端与协议](04-client-and-protocol.md)

## 1. 规则状态说明

本篇同时包含两类内容：

- **确定的工程规则**：服务端权威、20Hz fixed-step、客户端只发输入、有界世界、竖版、最多四人。
- **首轮候选数值/产品规则**：局长、复活、真人互撞、速度、食物数量等。它们用于支持估算和测试设计，最终需逐项确认并进入版本化配置。

任何标为“候选”的数字都不能散落成客户端魔法数。实施时应进入 shared 的 Snake 配置类型及服务端加载结果，客户端只把必要的表现值从权威状态/配置读取。

## 2. 世界与对象

### 2.1 坐标系

- 逻辑世界使用二维笛卡尔坐标，服务端内部坐标与 Cocos 展示坐标通过单一 adapter 转换。
- 首轮候选世界复用当前 shared 的 `MAP_WIDTH = 700`、`MAP_HEIGHT = 1500` 数值，形成明显竖向场地；目标所有权
  进入 Snake ruleset/manifest，不把现有全局常量当长期契约。
- 地图原点建议在中心，边界为 `[-350, 350] × [-750, 750]`。
- HUD 与安全区不改变世界坐标；客户端相机/画布负责留出顶部信息区和底部触摸区。
- 若可玩性测试证明 700×1500 过窄，应整体调整地图与出生/食物参数，不把参考档案的 3264×1920 横版尺寸直接搬来。

### 2.2 世界对象

| 对象 | 服务端权威字段 | 客户端可见摘要 |
| --- | --- | --- |
| Snake | id、head、direction、speed、length、body deque、alive、score、boost、respawnTick | 头部、采样身体、方向、外观、状态、分数 |
| DotFood | id、position、growth、score | 位置、类型 |
| StarFood | id、position、growth、score | 位置、类型、强调效果 |
| Wreck | id、position、growth、score、expireTick | 位置、类型、剩余表现时间可选 |
| Match | seed、tick、endTick、phase、winner/ranking | 倒计时、排名、结算 |

### 2.3 硬上限

所有集合都必须有显式上限，避免长局或恶意输入导致内存、Schema 或网络包无界增长：

| 项目 | 首轮候选上限 |
| --- | --- |
| 玩家 | 4 |
| 每蛇身体点 | 512；调优后可提高，但不得使用参考代码的 10,000 作为默认 |
| 普通食物 | 120 |
| 星形食物 | 8 |
| 死亡/加速掉落 | 全房 240 |
| 单快照对象数 | 按上述集合总上限 exact 校验 |
| C2S 输入 | 每客户端不高于房间总消息预算，并对 SnakeInput 单独限频 |
| 单世界快照 | 建议解码后小于 64 KiB；达到预算应降采样而非静默截断关键头部 |

这些上限是容量设计起点，最终值以 4 人长局压测为准。

## 3. 固定步长与确定性

### 3.1 时钟

- 房间公共 tick 维持 20Hz，即 `fixedStepMs = 50`。
- 渲染帧率不能进入权威公式。
- 服务端卡顿时按现有有界 catch-up 规则追帧，不允许无限补帧阻塞事件循环。
- 若蛇手感需要更细的碰撞步长，可以在每个 50ms Snake step 内做固定数量子步；子步数必须进入规则版本，不能由 wall-clock 决定。

参考档案 `LockStepMainLoop.js` 使用 60Hz 逻辑帧、每三帧消费一次 20Hz action frame。本项目首版不复刻客户端锁步，而是保留现有服务端 20Hz 主时钟；是否做三个确定性子步由碰撞测试决定。

### 3.2 数值口径

服务端可以使用有限精度量化减少跨运行时漂移：

```text
q(x) = round(x * 1000) / 1000
```

位置、速度积分和碰撞距离统一在确定位置量化。不要把参考实现中 `PI = 3.14` 等历史细节自动变成新规则；本项目应使用明确的角度/弧度转换和测试向量。

### 3.3 每 tick 更新顺序

建议固定为：

```text
1. 按 sessionId 稳定顺序读取本 tick 最新合法输入
2. 计算每条蛇的目标方向、转向和 boost 状态
3. 积分所有蛇头候选位置
4. 更新身体队列与加速消耗/掉落候选
5. 重建或增量更新空间网格
6. 统一判定墙、自身、蛇间碰撞
7. 统一判定食物/掉落拾取，解决同 tick 争抢
8. 应用死亡、掉落、复活与分数变化
9. 补充食物到目标数量
10. 检查结束条件并生成摘要/快照
```

“先按玩家逐个移动并立即碰撞”会让 Map 遍历顺序影响结果，应避免。相同 seed 和输入序列的测试必须钉住完整更新顺序。

## 4. 输入与移动

### 4.1 SnakeInput

每条输入只表达：

```ts
interface ISnakeInputReq {
  dirX: number;   // [-1, 1]
  dirY: number;   // [-1, 1]
  boost: boolean;
  seq: number;    // 同一 match/player 严格递增，重连后从权威 ackSeq 之后继续
}
```

服务端处理规则：

- exact keys；拒绝 NaN、Infinity、越界值和非整数 seq。
- 长度接近零的向量表示保持上一方向，不允许产生无定义角度。
- 方向向量由服务端归一化。
- `seq <= lastAcceptedSeq` 的重复或倒退输入不改变状态。
- 每 tick 只使用该玩家截至输入截止点的最新合法意图。
- 客户端不能提交 tick、坐标、长度、速度倍率或碰撞结果。

参考 `LockStepData.js` 的 9 bit 方向 + boost bit 只作为“方向与加速是输入”的证据。首版可用可读的 typed payload；只有测得带宽压力后才考虑位打包。

### 4.2 转向

设当前方向角为 `a`，目标角为 `target`，每 tick 最大转角为 `maxTurnPerTick`：

```text
delta = shortestSignedAngle(target - a)
nextDirection = a + clamp(delta, -maxTurnPerTick, maxTurnPerTick)
```

- 角度归一化到固定区间，例如 `[0, 360)`。
- 最大转角与 boost 是否不同必须进入配置；候选基线先保持相同，避免加速改变转向学习成本。
- 不允许 180° 瞬时掉头穿过自身身体。

### 4.3 位移

```text
speed = boostAccepted ? baseSpeed * boostMultiplier : baseSpeed
headNext = q(head + unit(direction) * speed * fixedStepSeconds)
```

首轮候选：

| 参数 | 候选值 | 说明 |
| --- | ---: | --- |
| `baseSpeed` | 160 unit/s | 需在真机和 700×1500 场地调优 |
| `boostMultiplier` | 1.6 | 参考实现默认 2 倍，仅作调参参照 |
| `maxTurnPerTick` | 9° | 对应 180°/s；最终以手感测试为准 |
| 输入上行频率 | 20Hz 上限 | 方向变化时立即发，客户端可合并不变输入 |

## 5. 身体、长度与成长

### 5.1 身体数据结构

服务端为每条蛇维护有上限的循环双端队列，头在索引 0：

- 移动时将尾部可复用点移到头部，避免每 tick 大量分配。
- 新头点记录量化位置和方向。
- 长度增加时扩展有效点数；长度消耗时从尾部收缩。
- 达到身体点硬上限后仍可增加分数，但视觉长度按上限封顶，或触发明确的长度上限规则。

这借鉴 `SnakeBodyComponent.js` 和 `CircularDeque.js` 的数据结构思想，但在纯 TypeScript 服务端重新实现，并把容量从参考档案的 10,000 收紧为本项目可压测的上限。

### 5.2 长度到身体点

首版建议采用线性、易测试的映射：

```text
visiblePointCount = clamp(
  ceil(length * pointPerLength),
  initialPointCount,
  maxBodyPoints
)
```

也可以将“逻辑长度”和“几何路径长度”分离：逻辑长度用于计分/消耗，身体点按固定 `pointSpacing` 沿历史轨迹采样。最终必须保证：

- 同一长度得到确定点数。
- 增长不会在一帧分配大量点。
- 收缩不会删掉头部。
- 快照恢复后的身体点数量与路径一致。

### 5.3 吃食物

```text
newLength = min(maxLength, oldLength + food.growth)
newScore  = oldScore + food.score
```

同一 tick 多条蛇都覆盖同一食物时，按稳定规则决胜，例如最小头心距离，其次 sessionId 字典序。不能依赖碰撞循环先后。

## 6. 食物与掉落

### 6.1 普通与星形食物

| 类型 | 候选 growth | 候选 score | 目标数量 | 用途 |
| --- | ---: | ---: | ---: | --- |
| Dot | 1 | 1 | 120 | 稳定成长主来源 |
| Star | 5 | 5 | 8 | 高价值争夺点 |
| Wreck | 1 | 1 | 动态、全房上限 240 | 加速/死亡产生 |

参考档案默认 Dot/Star 数量为 300/15、价值为 1/10，地图却是 3264×1920。目标世界面积和人数不同，不能直接照搬。

### 6.2 生成

- 生成位置来自本局命名 RNG 子流，例如 `food.spawn`，与玩家出生子流分离。
- 新食物不能与墙安全边距、蛇头出生保护区或现有实体严重重叠。
- 每 tick 限制补充数量，避免清屏后单帧尖峰。
- 尝试次数达到上限仍无合法位置时延后补充，不进入无限循环。
- 食物 id 由服务端生成且在本局内唯一。

### 6.3 加速消耗

候选规则：

```text
boostAccepted = requestedBoost && length > minBoostLength && alive
boostDebt += boostAccepted ? boostCostPerSecond * dt : 0
while boostDebt >= 1:
  length -= 1
  boostDebt -= 1
  按配置间隔在尾部生成一个 Wreck（受全房上限约束）
```

候选参数：`minBoostLength = 20`、`boostCostPerSecond = 3`。最终要验证新出生长度是否足以让玩家短暂体验加速，又不会因误触快速死亡。

### 6.4 死亡掉落

候选规则：按超出最小出生长度的部分折算掉落，限制每次死亡的对象数：

```text
dropBudget = min(maxDeathDrops, floor(max(0, length - spawnLength) * deathDropRatio))
```

沿蛇身均匀采样位置生成 Wreck，剩余长度价值可以聚合到单个掉落，不能为每个身体点都创建网络对象。

## 7. 碰撞

### 7.1 空间网格

- 将世界划分为固定尺寸 cell。
- 蛇身采样点、食物和掉落登记到 cell。
- 蛇头只查询当前 cell 与相邻 cell 的候选。
- cell 尺寸、插入采样间隔和碰撞半径进入规则配置。
- 每 tick 候选检查次数要有诊断指标，极端情况下不能退化为无界全量两两比较。

这借鉴 `MeshService.js`、`CollisionService.js` 和旧 TeamGame 的网格思路，但不复制其 Cocos 对象关系。

### 7.2 墙体

候选规则：蛇头圆与边界安全线相交即死亡。若后续要改成“碰墙滑行”或“穿越到对侧”，必须作为不同 ruleset，不在客户端单独实现。

### 7.3 自身

- 忽略紧邻头部的一小段身体，避免头点与自己的连续路径天然重叠。
- 头部与更早身体采样段相交则死亡。
- 碰撞应基于连续移动 swept segment 或足够细的固定子步，避免加速穿透细身体。

### 7.4 其他真人蛇

参考 `CollisionService.js` 的现代 MultiUGC 分支只有在两蛇至少一方是 AI 时进入蛇身碰撞，这不满足四真人 PvP 直觉。因此 SNAKE-OPEN-04 必须单独确认。

推荐候选规则：

- 蛇头撞到另一条蛇的身体：移动者死亡。
- 两头同 tick 相撞：较短者死亡；长度相同则双方死亡。
- 出生保护期间不造成或不接受蛇间碰撞，但仍受墙体约束。
- 所有对称情况先收集候选，再统一结算，避免遍历顺序偏置。

### 7.5 食物拾取半径

拾取判定使用蛇头半径、食物半径和统一倍率。参考档案 `EAT_DIS_FACTOR = 1.6` 可作为调参起点，不应不经尺寸换算直接使用。

## 8. 出生、死亡与复活

### 8.1 出生

- 每名玩家使用本局 seed 与稳定玩家顺序派生出生点。
- 出生点远离边界和现存蛇头/身体。
- 四个候选出生区在竖向场地中分散，不让一方总处于视野优势位。
- 出生方向指向场地内部。
- 候选保护时间 1.5 秒；保护结束 tick 由服务端明确记录。

### 8.2 候选复活制

若采用推荐的 90 秒计分制：

- 死亡后产生掉落、停止接受移动副作用。
- 候选 2 秒后在安全点以 `spawnLength` 和既有累计 score 复活。
- 倒计时最后不足复活延迟时可以不复活。
- 首版不提供客户端“看广告立即复活”或付费复活。

### 8.3 淘汰制替代方案

若选择最后存活：

- 死亡后本局不复活。
- 剩余存活数小于等于 1 时结算。
- 两名/多名同 tick 全灭需要平局或按此前分数/长度排序。
- Playing 掉线超时会直接影响胜负，需更严格定义。

复活制与淘汰制不能在实现中混搭；最终选择必须同时更新 state、UI、测试和结算证据。

## 9. 得分与胜负

### 9.1 候选计分制

- 吃食物和掉落增加累计 score。
- 加速消耗长度不扣累计 score。
- 死亡不清空累计 score，但复活长度回到初始值。
- 到达 `endTick` 后按以下稳定优先级排名：

```text
score 降序
→ 当前 length 降序
→ deathCount 升序
→ 最后一次达到该 score 的 tick 升序
→ sessionId 字典序（只作完全相同后的确定性兜底）
```

sessionId 兜底不应作为面向玩家的“公平规则”宣传，只用于消除无法区分时的不确定性。产品若需要展示并列名次，应在 state 中显式支持 tie。

### 9.2 结束条件

推荐候选：开局 3 秒倒计时后，正式计时 90 秒；`tick >= endTick` 时冻结本 tick 全部已接受结果，再进入 Settle。服务端不得以客户端倒计时归零为准。

## 10. 首轮候选参数汇总

| 分类 | 参数 | 候选值 | 来源/说明 |
| --- | --- | ---: | --- |
| 世界 | width × height | 700 × 1500 | 沿用当前项目竖版逻辑地图基线 |
| 时钟 | tickRate | 20Hz | 沿用 GameRoom fixed-step |
| 局长 | duration | 90s | 产品候选值；参考档案只证明存在限时模式，不证明固定 90 秒 |
| 移动 | baseSpeed | 160 unit/s | 需真机调优 |
| 移动 | boostMultiplier | 1.6 | 参考默认 2.0，先收敛手感 |
| 转向 | maxTurnPerTick | 9° | 需防穿透测试 |
| 长度 | spawnLength | 30 | 与参考 `SNAKE_MIN_LENGTH=30` 同量级，仅作起点 |
| 长度 | maxBodyPoints | 512 | 本项目网络/内存预算 |
| 加速 | minBoostLength | 20 | 候选 |
| 加速 | costPerSecond | 3 | 候选 |
| 食物 | dot / star | 120 / 8 | 按目标地图和四人缩减 |
| 复活 | delay / protection | 2s / 1.5s | 候选复活制 |
| 快照 | worldSnapshotRate | 10Hz | 与 20Hz状态摘要错开；压测后调整 |

## 11. 规则验收

- 相同 seed、配置、精确 roster 和输入序列产生相同最终快照与排名。
- 30/60/120fps 客户端得到相同权威结果。
- 方向零向量、180°掉头、最大转角、boost 临界长度都有纯函数测试。
- 身体增长、收缩、环形容量和快照恢复不丢头、不反序、不越上限。
- 同 tick 抢同一食物、头对头、多人同时死亡都有稳定结果。
- 加速、复活保护和倒计时全部基于 tick，不基于 `Date.now()` 漂移。
- 墙、自身、真人蛇碰撞符合最终拍板规则，并覆盖高速 swept collision。
- 所有实体集合、快照字节和每 tick 工作量有上限及超限行为。
- 参考档案中的 300 食物、10,000 身体点、AI 特例或横版地图不会被未经审查地继承。
