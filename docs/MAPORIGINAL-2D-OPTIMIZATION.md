## 1. 目标与范围

在保持现有地图位置、资源等级、完整 prefab、层内遮挡和四档 LOD 策略的前提下，减少源纹理驻留、
无效图集面积、首屏等待和大型表现配置对脚本包的占用。按以下顺序实施：

**冻结可复测基线 → 图集去重重排 → 带定位元数据的透明裁边 → 分组加载与释放 → GPU 压缩 → 大配置外置。**

静态/动画几何更新优化列为后续 O6。它不是图集和配置改造的退出前提。

本轮不调整原版格值、地图坐标、pivot、父子变换、资源等级和地貌选件规则；不新增 AOI、领地、军队、旗帜或 3D 地图。
原始 ELP、KTX、prefab 和反编译资料保持仓外只读；派生产物和九字段授权台账继续走已有工具。
不额外降低图片分辨率，不抽稀资源件、不删动画帧，不把全地图各级细节全部预烘为大型切片包。
减量分别统计独立图片、物理存储矩形、PNG 包体积与纹理驻留；图集文件数不作为单独的优化目标。

## 2. 当前实现与测量口径

### 2.1 素材管线

```text
仓外原包：KTX / 图集 XML / prefab / 地图字节 / 配置
  → tools/maporiginal-assets：解码、切片、展开节点、缩采样、重打包
  → apps/kits/mapOriginal/data/maps/s1：派生图片、二进制、核验元数据
  → apps/shared/src/kits/mapOriginal/content：生成的内容 TS
  → apps/Cocos/assets/resources/kits/mapOriginal/maps/s1：运行时素材镜像
  → MapoArtResources：resources.load + 引用持有
  → 可见区查询、prefab 求值、Mesh 合批 / 分块烘焙
```

kit 数据目录和 Cocos 资源目录是源产物与镜像关系，不能简单相加后声称运行时加载了两份。
shared/client/Cocos 脚本镜像分别通过 `sync:shared`、`sync:client` 更新，禁止手改镜像。

主画面使用 MeshRenderer + UIMeshRenderer，按固定层容器和层内画家序显示。
离屏分块使用隔离 layer、正交相机和普通 MeshRenderer，避免 UI 队列共享投影造成的错误。
运行时没有为每个地块建立独立 Cocos Sprite；prefab 节点图是数据，由纯逻辑展开为精灵几何。

定位仍取原版 `position / size / pivot / scale / angle / skew / mirror` 及父子变换。
存储像素已有缩采样：资源件限制在 256×192 内；城池和 top 装饰约 0.4 倍；道路约 0.5 倍。
**存储像素尺寸与世界显示尺寸是两个概念**，后者不能从裁后图片或图集格尺寸反推。

代码入口：[资源加载](../apps/client/src/kits/mapOriginal/view/MapoArtResources.ts)、
[网格批次](../apps/client/src/kits/mapOriginal/view/MapoMeshBatch.ts)、
[prefab 求值](../apps/client/src/kits/mapOriginal/logic/mapoScene.ts)、
[安装工具](../tools/maporiginal-assets/install_to_kit.py)。

**中远景水面使用静态填充色，并非近景水流 shader 的冻结帧**；本方案记录这个边界，不顺带改变水面表现。

### 2.3 文件统计与内存估算

以下统计来自上述基线的 S1 文件。MiB = 1,048,576 B，KiB = 1,024 B。

| 项目 | 基线 | 口径 |
|---|---:|---|
| 运行时资源目录 | 35 文件，20,124,431 B，约 19.19 MiB | 排除 `.meta`；包含图片、二进制、effect、两个 info JSON |
| PNG | 18 张，约 15.78 MiB | 文件大小，不是纹理内存 |
| 实际加载的 PNG | 17 张，RGBA8 估算约 151.13 MiB | 排除未被当前 loader 使用的 `minimap-mask.png`；无 mipmap |
| 二进制配置 | 13 文件，3,494,841 B，约 3.33 MiB | terrain、摆放表、几何和城池件库 |
| 二进制 gzip 试算 | 约 1.60 MiB | 各文件独立 gzip level 9 后求和，非已发布下载量 |
| 内容 TS | 16 文件，1,382,838 B，约 1.32 MiB | 源文件字节；不等于构建后 JS 体积或 JS 堆 |
| 分块缓存 | 上限 48 MiB | 与上面的源纹理另外计算；8 MiB 概览已在 151.13 MiB 内 |

纹理估算采用 `width × height × 4`。它不含 JS 对象、网格、图片解码暂存、宿主 UI、驱动开销；
也不是对整页 GPU 实测的替代。进入 L3 清掉分块缓存，但当前全部源图集依旧由页面持有。
PNG `.meta` 没有启用地图专用压缩预设，纹理 mipfilter 为 none。
项目虽有 `3d-default / 3d-alpha` 压缩预设，地图图片未绑定，不能算作已启用。

内容 TS 中较大的文件为 `decor.data.ts` 约 547.9 KiB、`terrain.data.ts` 约 365.9 KiB、
`bands.data.ts` 约 230.3 KiB。显示层 `terrain.bin` 原始 2,250,008 B，gzip 试算 1,091,106 B。
旧 README 中的 157 KB、111 KB 等历史数字不作为本轮基线；O0 更新与本方案相关的现状说明。

#### 2.4.2 资源图集的大画布与动画

320 张资源切片中，185 张被帧动画或纹理切换轨道引用；其余 135 张为其他切片。
分类按纹理引用确定，**不代表其他切片的节点没有位移、颜色或父级动画**，不能据此跳过节点更新。
动画相关来源为粮地路径下 169 张、烟雾 15 张、其他效果 1 张；`-1` 空纹理编号不计入图片数。

| 分类 | 张数 | 当前切片矩形面积折合 RGBA8 | 含源护边裁边后的矩形面积折合 RGBA8 |
|---|---:|---:|---:|
| 动画帧 / 纹理切换依赖 | 185 | 31.56 MiB | 1.26 MiB |
| 其他切片 | 135 | 13.61 MiB | 13.55 MiB |

这是切片面积之和，**不含装箱空隙，不是最终纹理内存**。动画相关切片占当前切片矩形面积的 69.87%，
主要减量来自小内容周围的大透明画布。完整帧序、原画布与锚点必须保留。

基础 / 雪地 / 沙地 prefab 分别引用 230 / 214 / 217 张图片，其中 170 张三者共用。
现状已有跨地貌复用，不能把 320 张图片直接按三套独立素材估算或除以三。

#### 2.4.3 含护边的装箱候选

“非透明占比”指 alpha > 0 的像素数 / 整页像素数，不等于直接可回收比例。
本次补充试算保持现有存储分辨率，完整 RGBA 相同的切片先去重；裁边取 alpha > 0 包围盒，
向外保留最多 2 px 原图护边（不超出原画布），再给每个矩形的每边预留 2 px 装箱空间。
使用 MaxRects BSSF 与多种确定性排序，不旋转；成功布局已检查不重叠、不越界。
仍未生成运行图集，也未验证边缘填充、实际采样、GPU 压缩块和引擎画面，因此只是**尺寸候选**。

| 图集 | 当前尺寸 / RGBA8 | 非透明占比 | 候选方式与尺寸 | 候选 RGBA8 |
|---|---|---:|---|---:|
| decor 单页 | 4096² / 64 MiB | 13.4% | 含源护边裁边，本次单页试排为 2048×4096 | 32 MiB |
| decor 两页 | 同上 | 同上 | 其他切片 2048² + 动画相关切片 512×1024；需分页支持 | 18 MiB |
| region | 2048×4096 / 32 MiB | 25.7% | 26 个条目共享 19 张图片，去重紧排到 2048²，无须裁边 | 16 MiB |
| city | 1024² / 4 MiB | 21.5% | 158 张切片原样重排到 512×1024 | 2 MiB |
| road | 1024² / 4 MiB | 10.8% | 36 个条目共享 18 张图片，无裁边 512×1024；追加裁边 512² | 2 / 1 MiB |
| river-top | 2048² / 16 MiB | 9.6% | 含源护边裁边后 1024² | 4 MiB |
| snow-top | 1024² / 4 MiB | 13.5% | 无裁边 512×1024；含源护边裁边 1024×256 | 2 / 1 MiB |
| desert-top | 512² / 1 MiB | 43.3% | 本次未找到页尺寸下降 | 1 MiB |

**修订此前 decor 2048² / 16 MiB 的估算口径**：初次试算未包含源图护边。
本次全部护边矩形连装箱间隔共 4,129,271 px，2048² 只有 4,194,304 px，需要约 98.45% 利用率；
单页试排未成功，但这也不证明数学上绝不可能。16 MiB 保留为待证目标，不能作为确定收益。
两页 18 MiB 已通过矩形试排，仍须比较分页的材质切换、draw call 与遮挡正确性。

若采用 decor 两页 18、region 16、city 2、road 无裁边 2、river-top 4、snow-top 1 MiB，
其余纹理保持，源纹理候选合计 **70.13 MiB**；再做 §2.5 小地图留白裁减为 **69.63 MiB**。
道路追加裁边可在此基础上再减 1 MiB；单页/两页、道路两种布局、雪 top 两种布局分别互斥，不能重复累加收益。
这些数字不含分组释放和 GPU 压缩，不含 48 MiB 分块缓存；PNG 下载体积要用真实产物另测。
O0/O1/O2 完成前，不能把上述估算或初版四项合计约 79 MiB 的估算记为已兑现收益。

本次临时证据位于 `.cache/maporiginal-image-composition/`：`report.json` 含 PNG 指纹、切片哈希、
引用与装箱坐标，`audit.py / reachability.py / page-trial.py` 可复核；该目录被忽略，不随仓库交付。
本文保留关键方法和数字，O0 仍需将统计能力整理为受维护的入口并补真实性能基线。

### 2.5 小地图、数据纹理与小图片的减量边界

**小地图**：当前 `minimap.png` 为 512²，alpha 包围盒是 `[0,128,512,384]`，
由 `bake_overview.ts` 把 overview 缩成 512×256 后垂直居中。O2 优先原样保存这块内容，
以 §4.3 的布局契约保持画面与导航一致，纹理候选从 1 降为 0.5 MiB。
与 overview 共用纹理、取消独立 minimap PNG 是另一个备选，理论可少持有 1 MiB，
但直接缩放与当前预缩小图的采样不同；须比较锯齿、抖动和可读性。
如为此新增整张 overview 的 mip 链，额外内存可能超过节省量，不能预先计为净收益。

**河流水色图**：`river-mask.png` 为 2048² / 16 MiB，含 17,347 种 RGB 值，三通道不同，
不是可直接替换成 R8 的灰度遮罩。83.59% 像素 RGB 为黑色，但分散在全图内部；
另有 142,612 个 alpha 为 0、RGB 非黑的像素。[当前水面 shader](../tools/maporiginal-assets/shaders/mapo-river.effect)
读取 RGB、输出 alpha=1，**alpha=0 不能作为可删像素的判据**。
优先沿 O3 按需释放与 O4 专用 GPU 压缩处理；稀疏分页须增加映射、采样和邻接护边，暂不排入本轮。

**小图片**：`river-fill.png` 为三个 2×2 平色块，文件 89 B；`grid-line.png` 为 8×8、两种 RGBA 值，文件 91 B。
可研究用常量或生成纹理表达，但本轮容量收益很小。选框已经复用切片，三张 256² 底纹合计仅 0.75 MiB。
未加载的 `minimap-mask.png` 只有 1,995 B，移出运行包不能算作当前加载显存的收益。

依据：[概览与缩略图烘焙](../tools/maporiginal-assets/bake_overview.ts)、
[小地图 UI](../apps/client/src/kits/mapOriginal/view/MapoMinimap.ts)、[水面导出](../tools/maporiginal-assets/build_surface.py)。

## 4. 图片数据契约

### 4.1 逻辑件与图片条目分离

同图复用只合并像素存储。逻辑件仍保留独立的资源值、variant、prefab、pivot、transform、颜色、层序和动画。
用稳定 `textureId` 引用图片条目，图集坐标由布局表解析；不得把格值直接用作可复用纹理的唯一身份。
去重需比较实际像素、尺寸与采样约定；路径可用于识别候选，不能仅凭名字相同合并不同像素。
道路基础 / 雪地的不同来源路径应能映射到同一图片条目，仍保留两套 clientResId、选件规则与 UV 镜像。

图片条目至少包含以下字段，O1/O2 在单一 schema 中生成：

| 字段 | 含义 |
|---|---|
| `textureId / atlasId / rect` | 稳定图片身份、图集身份、有效 UV 矩形 |
| `nativeSize` | 原始图片画布尺寸，用于来源校验 |
| `storageSize` | 已有缩采样之后、裁边之前的完整像素尺寸 |
| `trimRect` | 相对 storageSize 左上角的裁剪矩形，含保留的采样护边 |
| `layoutVersion / contentHash` | 布局版本与内容绑定；不改变 prefab 的 pivot |

`source` 真路径和转换说明留在可审计元数据中，不必把长路径重复带入每个运行时节点。
优先在每个现有图集族内重排；多图集分页仅在内存/平台上限或地貌按需加载收益明确时引入。
分页不能按 atlasId 全局重排透明精灵，应保持原来的画家序及跨页提交顺序。
O2 对照 decor 单页与“其他切片 / 动画相关切片”两页方案；同一切片被多类节点引用时仍只存一份。
两页只是纹理布局，不能用来判定节点是否静态；实时和离屏烘焙都按原序生成连续纹理批次，
不把全部动画提前或延后绘制。布局验收需同时报告内存、draw call、材质切换及重烘结果。

### 4.2 裁边后的定位

保留原节点 `size = (Nw, Nh)`、`pivot = (px, py)`、锚点和完整父矩阵。
设 storageSize 为 `(Sw, Sh)`，trimRect 为 `(tx, ty, tw, th)`，像素原点在左上，节点局部 y 向上：

```text
xLeft   = Nw × (tx / Sw - px)
xRight  = Nw × ((tx + tw) / Sw - px)
yTop    = Nh × (1 - ty / Sh - py)
yBottom = Nh × (1 - (ty + th) / Sh - py)
```

先生成这四个局部点，再走原本的父子矩阵、skew、旋转、缩放和世界换算。
**不能把裁后宽高直接替换原 size 并继续套原 pivot**，也不能重新按图片底边定位。

当前镜像通过翻 UV 实现。裁边后水平镜像的几何范围应使用 `tx' = Sw - tx - tw`，
垂直镜像应使用 `ty' = Sh - ty - th`，同时保留正确的 UV 方向；需覆盖非中心、越界 pivot 与双向镜像。
帧动画每帧独立保存裁边信息，共享同一原始节点锚点，换帧不能跳动。

仅裁确定不参与显示的透明区；不得用 alpha 阈值删除半透明阴影。
保留线性采样需要的透明护边和边缘 RGB，明确 padding/extrude 规则，禁止再次以粘贴蒙版乘 alpha。
运行时 shader 的乘色/加色与透明规则改变时，必须重新验证可裁剪条件。
GPU 压缩、mipmap 所需的护边另行验证，不能用当前 2 px 间隔直接推断所有级别都安全。

256² 草/雪/沙重复底纹继续独立存放并保持 REPEAT、整数周期和 POT；不塞进普通裁边图集。
颜色蒙版、法线图、格线、选框和概览不参与第一批通用 alpha 裁边。
每类图片登记 shader 实际读取的通道、alpha 用途与采样方式；水色图按 §2.5 保留有效 RGB，
不能把透明精灵的裁剪规则自动套到数据纹理。

### 4.3 小地图裁边与导航契约

小地图作为独立 O2 子项验证，不套用 prefab pivot。保留未裁画布 `sourceCanvasSize=[512,512]`
与 `contentRect=[0,128,512,256]`；新存储图为原样截取的 512×256，不再次缩采样。
UI 导航区域仍为正方形，内容图片居中显示、宽度不变、高度为导航区域的一半；
新纹理 UV 覆盖整张存储图，不能再把原画布中的留白比例当作新纹理的 UV 裁切范围。
世界坐标映射、点选与视口框共同遵循这个内容矩形，避免只改 PNG 导致内容拉伸或点击错位。
检验中心、四个地图边界、上下留白点击和视口框；记录原图与新图的内容像素逐字节一致。

## 5. 加载、生命周期与配置组织

### 5.1 资源组和需求

先在现有 resources 路径下拆加载生命周期，再迁移 Asset Bundle，避免同时改引用、布局和包路径。
加载复用框架 [AssetLease](../apps/client/src/view/scene3d/AssetLease.ts) 与
[Cocos loader](../apps/client/src/view/scene3d/cocosAssetLoader.ts)，不重写另一套引用计数、取消和超时系统。
它是通用资产加载件，消费它不要求地图改成 3D 舞台。

| 资源组 | 内容 | 持有条件 |
|---|---|---|
| overview | 概览、缩略图、基础标记与可先显示的地名数据 | 页面打开即加载，首先交付 |
| geography | 重复底纹、沙雪多边形、山体、道路、静态河流及 top 数据 | L0 显示、L1/L2 补烘任务需要 |
| resources | 资源 prefab、资源图集、显示层格值及相关地貌判定 | 非流畅 L0、需要资源件的 L1 烘焙；点选数据另独立持有 |
| cities | 城池模型图集与件库 | L0/L1；远档标记不依赖完整城市图集 |
| effects | 水流 effect、河色蒙版、法线图、格线、选框 | 按画质、LOD 和选择状态分别需求加载 |

逻辑分组不意味着马上复制或拆开每张物理图集。共享图片只加载一份，先支持按 LOD 分组；
按地貌分页在 O1/O2 后比较 draw call、边界混合场景与内存收益再决定。
L1/L2 缓存不是免加载源素材：补块时必须持有对应源资产，完成后才可按策略归还。

需求状态至少有 `idle → loading → ready → releasing`，失败可重试；只有同代际、同地图版本的结果可安装。
页面先展示 overview，组未齐时保留同源底图；不能把缺源烘出的半张块标成 ready。
新路径下硬错误需保留资源地址和错误码，不再无声吞掉解析失败；UI 是否可继续由组的必需性决定。

出档释放可设短宽限避免来回捏合反复加载，具体时长在 O0/O3 实测后冻结；关闭页面立即取消在途请求。
已经成功的租约须显式 release；取消 signal 不代表可立即释放仍在渲染的资产。
节点、材质、烘焙任务和帧末 GPU 提交不再引用后，才能归还纹理租约；保留迟到回调与幂等释放保护。
烘焙器目前会持有源材质，进入不需要源图的状态时必须一起解除这类引用。

### 5.2 地图数据生命周期

地图级数据持有者 `MapoDataStore` 显式持有显示格、地貌带、摆放表、几何库与展开件。
View 负责加载和注入，Logic 只消费纯数据；关闭或切图时解除引用。不能让模块单例永久保留上一张地图。
若保留跨页面 CPU 缓存，应有独立预算、版本 key、淘汰和报告，不能把它记入纹理缓存的 48 MiB。

缓存身份至少绑定 `mapId + contentVersion + atlasLayoutVersion + lod + pixels + quality/details + tile`。
版本或布局切换应取消旧烘焙、作废旧块，源图片、UV、配置必须作为同版本集合安装；不在一个帧里混用两版。

### 5.3 Bundle 与配置存储

O3 的独立地图包候选根为 `apps/Cocos/assets/bundles/kit-mapOriginal-s1/2d/`，bundle 名为 `kit-mapOriginal-s1`。
O3-B2 实施前核对安装工具、宿主包归属与 Creator 导入规则后冻结；新路径未创建前不得写成现状。
包内按上述逻辑组组织，是否放远端由平台构建配置决定，不在代码拼 CDN 地址。
切换后更新安装器、确定性 UUID、加载路径、台账和机检，不在 resources 中留下第二套可发布副本。

| 数据 | 目标方式 | 理由 |
|---|---|---|
| 格值、山体/道路/河流摆放、几何 | 二进制＋TypedArray/DataView，优先维持现有定长布局 | 稠密查询与现有二分裁剪已适合，不改成海量 JSON 对象 |
| 客户端 prefab 树、轨道、帧表、图集布局 | 按需数据资源；O5 比较外置 JSON 与带字符串表的二进制 | 优先解除脚本耦合，再依据解码时间与堆占用决定格式 |
| 图层顺序、LOD 阈值、小型规则 | 小型 TS 常量和类型 | 易审阅、易检查，外置收益有限 |
| shared 通行层 | 本轮保留纯 TS RLE 入口 | shared 零依赖，服务端不能为此直接读取客户端资源；未来通过宿主注入扩展 |
| 构建来源、校验说明 | kit-only JSON 与授权台账 | 保持审计能力，运行时无需携带全部长路径 |

新增运行时 manifest 记录 mapId、schemaVersion、contentVersion、atlasLayoutVersion、各组依赖与字节数。
二进制新增/升级头时包含 magic、版本、字节序、记录数、段偏移和边界；已有严格长度校验继续保留。
采用稳定 ID、共享字符串/纹理表和明确缺省值；不得以量化体积为由损失 transform、越界 pivot 或动画语义。

内容哈希绑定生成源与布局；平台纹理变体的实际文件校验由构建清单绑定，不能拿源 PNG 的 hash 校验 ASTC 文件。
继续使用 Creator 的版本化资源缓存机制，不另造一套浏览器私有缓存。传输 gzip/Brotli 需在实际发布服务验证
Content-Encoding、缓存和平台支持；压缩源文件的体积不等于最终包或网络流量。

**依赖**：O3；压缩画质试验可在 O2 后并行准备，不改变正式产物。
**风险**：中，关注半透明边缘、设备格式支持和 fallback 体积。

**落点**：图片 meta 生成策略、Creator builder 的地图专用预设、构建产物检查、桌面发布重放。
源 PNG 保留；普通颜色图集先比较 ASTC 4×4 / 5×5，按发布平台验证可用格式并保留 PNG 回退。
蒙版、法线、格线和选框分别对照，不能直接套 3D 的 8×8 预设。
水色图按 shader 实际读取的 RGB 验收，包括 alpha=0 区域；压缩前处理不得依据透明度清除这些 RGB。
法线图按实际 RG 采样与水流结果评价，不以整张图片的平均颜色误差替代。

ASTC 无 mip 估算为 `ceil(width/blockWidth) × ceil(height/blockHeight) × 16` B；
RenderTexture 仍按自身格式计费，不因源图压缩自动减少。增加 mipmap 会增加存储和显存，本批默认不全局打开。
若另开 mipmap 试验，必须同时验证图集护边、远端串色、REPEAT 接缝和 WebGL1 约束。

**退出**：发布包实际包含预期变体，桌面发布运行时实际选择格式被记录；模拟不支持 ASTC 时走 PNG 且可显示；
按 §7 给出质量报告与源纹理内存变化。不能以 `.meta` 勾选或编辑器 PNG 预览替代发布验证。

### O5 · 客户端大配置外置

**依赖**：O3 的 manifest、版本和数据生命周期；按主顺序在 O4 后交付。
**风险**：中，异步就绪与 schema 漂移。

**落点**：`pack_decor.py / scene_export.py / build_tops.py` 等导出器、`content/*.data.ts` 消费入口、
数据 reader、manifest 和原包/内容回归。

**交付**：先外置 decor 节点与动画、top 场景、图集布局；试验外置 JSON 与二进制，记录原始/传输大小、
解码耗时和保留堆，再选择格式。保留小型 TS 规则和 shared 通行入口；不得在 shared 中引入 Node、DOM、cc、网络或文件读取。

**退出**：节点树、transform、颜色、纹理引用与关键时间点的求值结果等价；截断、错版本、越界偏移、
非法 ID 明确拒绝；构建脚本体积和解析指标可复测改善。若二进制没有足够收益，可采用外置 JSON，
不能仅以“二进制更先进”作为格式依据。

### O6 · 静态与动画更新优化（后续批次）

**依赖**：O2/O3/O5。**落点**：mapoScene、MapoDecorRenderer、MapoTopRenderer、MapoMeshBatch。
预编译静态节点和局部矩阵；区分静态数据与受父动画影响的数据；只更新变化的几何/属性范围。
需要混合提交时按原画家序拆连续段，不能先画全部静态件再画全部动画件。

**退出**：可见区不变且无动画时不重复展开/上传；有动画时保持帧语义、遮挡和乘加色；
报告 CPU 时间、每帧上传字节和 draw call 的实际取舍，三者不能只挑有利项报告。

## 8. 技术取舍与参考

- **PNG 源图继续保留**：便于确定性重打包与像素核验；发布变体由平台构建生成。
- **WebP 不作为显存方案**：它主要影响包与传输，GPU 压缩纹理才直接改变纹理驻留格式。
- **不盲目采用 KTX2/Basis**：本轮优先走已用 Creator 3.8 的构建/加载链；引入新转码链需单独验证运行时与小游戏兼容。
- **不逐格拆图片请求**：图集族和地图包仍是加载单位，空间分片需以实测收益证明额外索引与请求值得。
- **不全量 JSON 化或二进制化**：按大小、访问模式、共享边界选择；当前 225 万格的一字节显示层继续保留。
- **不改变水面和既定采样精度**：中景静态水面与原图缩采样是已知表现边界，恢复更高精度另立可对照目标。
- **S2 原创素材另按作者态设计**：独立图片、组合件和地图实例分层；环境覆盖、主体、等级附加件及动画部件
  可在新美术制作时分开，以增加复用。不能将此当作现有 S1 合成 PNG 可自动无损拆解的证据，也不扩大本轮实施范围。

外部机制参考（2026-09-24 查阅；支持矩阵仍以目标设备实际选择的格式为准）：

- [Cocos Creator 3.8：Compressed Textures](https://docs.cocos.com/creator/3.8/manual/en/asset/compress-texture.html)：
  构建多格式纹理、按设备选择、PNG/WebP 与 GPU 压缩的内存区别、通用格式回退。
- [Cocos Creator 3.8：Asset Bundle](https://docs.cocos.com/creator/3.8/manual/en/asset/bundle.html)：
  按需资源包、远端/本地/小游戏子包及版本组织。移动到 Bundle 不等于已经做到按需加载。
- [本仓客户端文档](CLIENT.md)：Logic/View 边界、通用 AssetLease 的取消/失败/迟到释放语义。

### O3-B1 实施与验收（2026-09-24）

`MapoArtResources` 改为独立分组，加载、超时、取消和引用计数复用框架 `AssetLease`。
`overview` 首先交付；其他组可各自完成、失败和重试。失败保留资源地址，加载错误使用框架错误码，

超时为 15 秒，失败后至少间隔 1 秒再试；离开需求的在途请求立即取消，已完成组保留 5 秒，重入取消释放。

实际需求如下。`effects` 按用途拆为三组，格值另设 `selection` 组，避免一次点选钉住资源图集：

| 组 | 需求 | 退出后的处理 |
|---|---|---|
| overview | 全档 | 关页时释放概览、小地图、基础 sprite effect |
| geography | L0–L2 | L3 宽限到期释放底纹、雪沙块、山体、道路、静态河流、top 及解码数据 |
| resources | 非流畅 L0–L1，依赖 geography 与 selection | 宽限到期释放资源图集；点选数据独立决定去留 |
| cities | L0–L1 | 宽限到期释放完整城市图集、件与摆位；远档标记仍独立显示 |
| water | 非流畅 L0 | 宽限到期释放水流 effect、蒙版与法线 |
| grid | L0 | 宽限到期释放格线图 |
| choose | 有选择且 L0–L1 | 宽限到期释放选框图 |
| selection | resources 需要，或存在选中格 | 显示格、惰性通行层不依附资源图集；关页全部清除 |

**数据和生命周期**：

  `decor.data.ts` / `tops.data.ts` 只留类型和小常量。

  `.bin` 是 Creator 导入约定，内容仍是 JSON。路径、manifest 内容版及布局版绑定这些外置配置。

  离线工具通过 `read_presentation.ts` 显式注入，Node 文件读取不进入运行时或 shared。

**格式选择实测**（Apple M4，Node v26.5.0；`format-final.json`）：

| 格式 / 指标 | decor | tops | 合计 |
|---|---:|---:|---:|
| 外置 JSON 原字节 | 626,411 B | 87,991 B | 714,402 B |
| JSON gzip level 9 | 61,719 B | 12,084 B | 73,803 B |
| 字符串字典 + f64 二进制候选 | 555,743 B | 76,547 B | 632,290 B |
| 二进制 gzip level 9 | 56,770 B | 12,167 B | 68,937 B |

二进制保留全部字段与 f64、不量化，只比 JSON 少 4,866 B 的 gzip 估算值；
其解码中位数约为 JSON.parse 的两倍以上，20 份结果经显式 GC 测得的每份保留堆约为 JSON 的两倍。
本批选择 JSON。gzip 是离线传输估算，未把源包体积当作实际 HTTP 下载量。
JSON.parse 本身只占加载的一部分；当前发布 reader 连同 UTF-8、CRC 与完整校验，
decor / top 中位数分别 **6.97 / 1.02 ms**，p95 **7.75 / 1.16 ms**。
原三份 TS 的隔离冷编译中位数合计约 **6.58 ms**，执行约 **2.00 ms**；
这些是同一桌面运行时微基准，不能相加推算整页启动时间或声称各设备同比加速。
保留堆按解析结果分别记录；TS 编译产物持有量另列，不与数据对象重复求和。
