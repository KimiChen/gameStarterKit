Redis / MySQL · 已提交状态与操作凭据
游戏进程外 · 通过接口协作

可同仓库、同机器部署；进程独立，资源设限。连接入口初期可与业务合并。

进程内

请求、提交、同步

负责

权限与参数校验 → 受保护地加载、计算、提交 → 自动同步。业务响应不重复携带玩家状态。

恢复

进程退出后重载已提交状态，按原操作编号查证，客户端重连补齐。

进程外

监控独立，保留轻量输出

游戏提供

脱敏日志、指标、关联编号、健康与就绪状态。

外部负责

采集、存储、检索、分析和告警。

故障边界

监控停机不阻塞普通请求；遥测有界丢弃，关键审计可靠保留。

进程外

外部启停，游戏配合排空

游戏提供

版本、就绪状态、排空入口和进度。排空：停止接新工作，完成或交接在途工作。

外部负责

构建、发布、托管重启、资源限制与扩缩容。

发布顺序

新实例就绪 → 接流量 → 旧实例排空退出。代码回退前检查数据兼容。

进程外

后台管流程，游戏管规则

读取

提供受权限与范围限制的查询；外部做页面与汇总。

修改

封禁、补偿走业务命令，仍校验权限、幂等与审计；不开放任意改库。

维护

配置编辑发布、备份恢复外置；游戏使用有效配置并提供受控维护接口。

开发机 / CI

AI 工具不常驻游戏进程

框架提供

真实契约、标准示例、正式初始化入口、稳定错误码与关联信息。

工具负责

查接口、写业务、启动隔离环境、执行验证、定位问题。

效率衡量

固定需求与模型，比较手写改动、反馈耗时、人工介入和修复结果。

按需独立

先可靠登记，再后台执行

游戏登记

权威结果与交付凭据原子提交，不能先扣款再单独入队。

后台执行

认领、重试、确认，复用正式领域写入口。

恢复

消费者退出后重新认领；重复投递不能重复发奖。

按需独立

计算与房间是不同角色

重计算

独立进程限制 CPU、内存和队列；计算可重做，发奖仍走正式提交。

实时房间

维护局内状态，永久资产通过统一入口结算。

恢复边界

内存中的对局不会自动恢复；续局另需快照或重放。

最小化仍保留权限、并发保护、幂等和审计。Redis 需要持久化与备份；进程重启不能替代存储恢复。
02 / 目标对应

目标决定功能与边界

目标设计验证
核心最小按需装配；监控、部署、后台外置。依赖少、资源有界，外围停机不拖住无关业务。
AI 高效开发接口可查，示例能跑，验证有统一入口。实测手写改动、耗时、人工介入与定位结果。
双端一致共用协议；提交后自动同步。不复制协议或重复返回状态；重连、删除、乱序正确。
异常可恢复状态外置，提交有保护，重试有依据。终止进程后重载，不重扣、不重发。
多进程可扩展按角色扩容，路由、认领与排空明确。多实例结果一致，容量收益和瓶颈有实测。
可正式维护独立告警、发布与备份恢复。故障、回退、恢复都有演练证据。
03 / 开发顺序

分步验证，最终完整交付

步骤是内部顺序，不是分多次交付；独立工作可并行。

01 / 完整设计

确定交付范围

确定模块、接口、数据权威、进程边界与验收标准。

完成标准

范围表、接口约定、验收清单。

02 / 核心业务链

做通一次完整请求

共用协议 → 校验 → 加载与计算 → 提交 → 自动同步。

完成标准

正常、失败、重复请求和重连均正确。

03 / 独立运行与恢复

验证多进程和故障

实现角色启动、路由、写保护、任务接续与排空。

完成标准

单／多实例结果一致；退出后可恢复。

04 / 配套与所选能力

完成本次必要配套

接上监控、部署、后台、备份、AI 工具和所选业务。

完成标准

配套独立运行，所选业务的保障不遗漏。

05 / 整体验收交付

必要能力全部通过

联调、真实存储、容量、故障恢复、发布回退统一验收。

完成标准

交付代码、操作说明和证据；阻断项清零。

交付范围

核心 ＋ 必需配套 ＋ 所选能力的完整保障 ＋ 验收证据。

范围内的能力可以后写，不能漏交付。未选用的支付、排行、房间等，不强制加载；一旦启用，相应保障也必须完成。
