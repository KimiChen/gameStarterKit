# 《地下矿业公会》美术表现与资产制作方案

> 文档版本：0.1（方案草案）
>
> 编写日期：2026-08-28
>
> 适用范围：挂机玩法 Demo 的视觉设计、UI、场景资产与动效制作
>
> 设计基线：750×1624 竖屏、Cocos Creator 3.8.8、FairyGUI 1.2.2

## 1. 结论

首版采用**原创 Q 版扁平卡通 + 纵向矿井剖面 + 卡片式远征**。

矿场主界面借鉴纵向矿井游戏对“不断向下探索”的空间表达，但不制作复杂的自由行走、房间模拟或逐帧人物
动画。远征使用地图节点和任务卡，不制作可移动大地图或实时战斗。整体通过少量模块化图片、FairyGUI
组件和 Cocos 程序动效形成游戏感。

该方向在表现力和制作成本之间最平衡：

- 比纯图标、表格式挂机界面更像一款完整游戏；
- 比像素序列帧更容易维持人物比例、光照和轮廓一致；
- 比 2.5D、等距视角和动态基地房间更容易拆分、适配和验证；
- 大部分动效可以由位移、旋转、缩放、透明度和粒子完成；
- 场景、人物、建筑和远征插画可以分批制作，不要求一次完成大型资产库。

## 3. 视觉定位

### 3.1 关键词

- 温暖、可靠、忙碌；
- 幽暗矿层中的灯火；
- 木质脚手架、黄铜机械、旧钢轨和帆布；
- 轻冒险、轻工业，不做压抑恐怖；
- 大轮廓、低细节、高辨识度；
- UI 信息优先于装饰。

### 3.2 造型语言

- 人物采用约 2.5～3 头身比例，手脚和工具适度夸张；
- 建筑采用圆角矩形、梯形和粗管道等简单几何形；
- 所有可交互设备使用明显的高亮边缘和暖色工作灯；
- 岩层和背景使用大色块，避免高频纹理抢占文字可读性；
- 图标采用“单一主体 + 深色描边 + 少量高光”，不使用复杂背景；
- 光线统一从左上方或正上方进入，资产不得各自使用冲突光向。

### 3.3 建议色板

| 用途 | 建议颜色 | 说明 |
| --- | --- | --- |
| 最深背景 | `#182129` | 主矿井底色 |
| 岩层中间色 | `#35434D` | 洞壁、非交互结构 |
| 木材 | `#8A5B3D` | 脚手架、箱体 |
| 黄铜 | `#C88A3D` | 设备与升级装饰 |
| 主灯光 | `#F3BE58` | 工作中、可领取、重要反馈 |
| 冷光 | `#57C7BE` | 菌光洞窟、辅助信息 |
| 危险色 | `#E66555` | 容量溢出、行动力不足、失败 |
| 普通文字 | `#F4F0E8` | 深色背景上的主要文字 |
| 次级文字 | `#AEBAC2` | 说明、时间、次要数据 |

状态不能只依赖颜色表达。满仓、锁定、可领取和资源不足同时使用图标、文字或形状差异，兼顾色觉辨识。

## 4. 750×1624 主界面结构

主界面保持单手操作和信息层级稳定，不因矿层解锁反复移动核心按钮。

```text
┌──────────────────────────────┐
│ 安全区 / 标题 / 设置          │
├──────────────────────────────┤
│ 矿石   碎片   行动力   声望    │  固定资源栏
├──────────────────────────────┤
│ 仓库库存 / 容量     [全部收取] │  首要操作
├──────────────────────────────┤
│                              │
│      纵向矿井剖面主舞台        │
│  矿井层 ─ 矿工 ─ 矿车         │
│            │                 │
│          升降机               │
│            │                 │
│  深层入口 ─ 设备 ─ 工作灯      │
│                              │
├──────────────────────────────┤
│ 开采 / 运输 / 有效产率 / 瓶颈  │
├──────────────────────────────┤
│  矿场     矿工     远征        │  固定底栏
└──────────────────────────────┘
```

布局原则：

1. 顶部资源栏和底部导航固定；
2. 中间矿井区域允许纵向滚动或分层切换；
3. 收取按钮始终位于拇指容易触达的位置；
4. 开采、运输和有效产率同时出现，瓶颈不藏在二级页面；
5. 长数字使用统一缩写，点击后可查看准确整数；
6. 刘海、圆角和底部手势区通过运行时安全区适配，不写死在背景图内。

## 5. 矿场场景表现

### 5.1 纵向剖面

矿场不是可以自由移动的地图，而是一张由模块组成的动态信息面板。每一层由洞壁、脚手架、设备、岗位、
矿物和灯光组成。玩家首先看到当前正在工作的区域，更深层以暗色轮廓、锁链或雾气表示尚未解锁。

建议把场景拆成以下层级：

1. 远景岩壁和深度渐变；
2. 洞穴开口、支撑梁和轨道；
3. 矿井、升降机、仓库等设备；
4. 矿工、矿车和矿石；
5. 工作灯、尘埃、火花和收取反馈；
6. 数值标签、岗位标记和点击热区。

背景和装饰不应包含运行时文字、等级数字或价格，以便本地化和数值更新。

### 5.2 建筑成长

四类建筑分别为矿井、升降机、仓库和公会大厅。首版每类只制作三个外观阶段，而不是每一级一套图：

| 外观阶段 | 对应等级建议 | 表现 |
| --- | --- | --- |
| 简陋 | 1～2 | 木梁、手摇装置、少量灯光 |
| 稳定 | 3～4 | 黄铜机械、电动部件、更多轨道 |
| 成熟 | 5 | 强化钢架、醒目标牌、完整工作灯 |

等级变化优先通过增加附件、灯光和轮廓复杂度表现。不要完全替换整张场景，以免资产量和加载量随等级线性增长。

### 5.3 瓶颈表达

- 开采受限：矿井旁出现等待装载的空闲矿车和“开采不足”标签；
- 运输受限：矿石在升降机入口堆积，升降机显示红色负荷；
- 仓库接近满：仓库箱体逐步填充，资源栏出现容量提示；
- 仓库已满：停止增长表现，使用明确的“已满”文字和一次轻微提醒，不持续闪烁；
- 产能平衡：设备使用稳定暖灯，隐藏警告标记。

动画只解释权威状态，不制造不存在的产量。仓库已满后不得继续播放矿石不断入库的误导动画。

## 6. 矿工角色表现

### 6.1 角色辨识

首版四名矿工用轮廓、主色和工具区分：

| 角色定位 | 主色与轮廓 | 标志道具 |
| --- | --- | --- |
| 强凿岩手 | 铁灰、宽肩 | 大号铁镐 |
| 强运输员 | 橙棕、背架轮廓 | 绳索与矿石背架 |
| 勘察专精 | 青绿、轻巧 | 提灯与地图筒 |
| 生存专精 | 米白、方形药箱 | 护目镜与医疗包 |

头像、半身像和场景小人必须共享发型、帽子、主色和标志道具。角色在 64～96 像素显示尺寸下仍应能凭轮廓
区分，不依赖姓名文字。

### 6.2 角色动画

首版不制作复杂骨骼系统和长序列帧。角色图片按头部、身体、前臂和工具做少量拆分，用节点旋转和位移完成：

- 待机：身体轻微呼吸、头灯缓慢明暗；
- 凿岩：手臂和铁镐围绕固定轴摆动；
- 运输：角色与背架整体小幅上下移动；
- 远征中：主场景岗位留空，远征卡显示行走剪影或灯光扫动；
- 归队：角色图标从远征入口移动回岗位，随后恢复正常循环。

角色动画只需要表达“正在工作、离岗、归队”三个状态，不承担精确生产计时。

## 7. 远征页面表现

### 7.1 地图结构

远征使用一张竖向遗迹路线图，首版固定三个地点：废弃坑道、菌光洞窟、古代遗迹。地点之间以轨道、绳桥或
洞穴通道连接，未解锁节点覆盖雾气和锁标记。

每个地点由一张横向插画卡和一枚地图节点组成：

- 废弃坑道：暖棕岩层、旧木架、低风险；
- 菌光洞窟：青绿色冷光、巨型菌类、中等风险；
- 古代遗迹：深蓝石材、黄铜机关、金色核心光，高价值。

### 7.2 任务卡

任务卡必须展示：

- 地点名称和插画；
- 任务时长与预计归队时间；
- 行动力消耗；
- 编队人数、当前能力、最低能力和推荐能力；
- 派遣后矿场有效产率变化；
- 可见奖励范围，不显示私有 seed 或准确隐藏结果；
- 锁定、进行中、待领取和已领取状态。

开始远征前的确认弹窗重点表现“收益与机会成本”，不能只放一个醒目的出发按钮。

### 7.3 结果表现

结果弹窗使用统一构图，不为 C/B/A/S 分别制作完整大图：

1. 地点插画作为暗化背景；
2. 队伍从洞口返回的剪影；
3. 等级字母和对应边框材质；
4. 矿石、碎片、声望依次出现；
5. 奖励图标飞入资源栏；
6. 完成后出现关闭或继续查看按钮。

等级必须同时用字母和边框造型区分，不能只依赖灰、蓝、紫、金四种颜色。

## 8. UI 组件规范

### 8.1 组件风格

- 面板：深色岩石底板 + 木材或黄铜细边；
- 主按钮：暖黄色，按下时缩放并降低亮度；
- 次按钮：深蓝灰底，亮色描边；
- 禁用按钮：降低饱和度并保留明确原因文字；
- 进度条：资源使用矿车槽或箱体填充，行动力使用提灯电量或圆形刻度；
- 弹窗：统一标题条、关闭按钮、安全边距和底部操作区；
- 图标：透明背景，不把数字、角标和品质框画进主体图片。

按钮、面板、标签、品质框和进度条优先使用 FairyGUI 组件、九宫格与运行时文字。不要把完整页面生成为一张
不可交互的大图。

### 8.2 文本与数字

- 运行时文字统一使用项目字体，不在图片中烘焙中文；
- 主要资源数字必须拥有稳定宽度，增长时不引发布局左右跳动；
- 标题、资源、正文、提示至少形成四级字号；
- 资源不足、状态冲突和网络错误使用可读文案，不只显示错误码；
- 倒计时在最后一分钟可以提高强调，但不使用每秒全屏闪烁。

## 9. 动效策略

首版优先使用程序动效，减少序列帧资产：

| 对象 | 推荐动效 | 不推荐做法 |
| --- | --- | --- |
| 钻头、齿轮 | 匀速旋转、轻微抖动 | 大量逐帧机械动画 |
| 镐子 | 围绕手腕轴摆动 | 为每名矿工制作完整动作序列 |
| 升降机 | 上下位移、到站缓动 | 复杂绳索物理 |
| 矿车 | 沿固定路径移动 | 自由寻路 |
| 矿石 | 弹跳、缩放、曲线飞入 | 在背景图中预绘运动轨迹 |
| 工作灯 | 透明度呼吸、局部光晕 | 大面积动态光照系统 |
| 尘埃、火花 | 少量粒子 | 多层全屏粒子和后处理 |
| 升级 | 附件出现、金光扫过、数字对比 | 整场景长过场 |
| 领取 | 图标依次出现并飞入资源栏 | 无法跳过的重复长动画 |

所有循环动画在页面失焦、切后台或对应对象不可见时暂停。动画不得驱动权威时间、库存和奖励状态。

## 10. 首版资产清单

### 10.1 场景资产

- 1 张纵向矿井远景背景；
- 4 组可重复岩层与洞口模块；
- 木梁、轨道、管道、灯具、箱子等 10～15 个通用装饰；
- 矿井、升降机、仓库、公会大厅各 3 个外观阶段；
- 1 套矿车、矿石堆和仓库填充状态；
- 3 张远征地点插画；
- 锁定雾气、路线和地图节点组件。

### 10.2 人物资产

- 4 张方形角色头像；
- 4 套简化场景小人；
- 每人拆分身体、手臂、工具和头灯等必要部件；
- 1 套通用远征队伍剪影；
- 首版不制作换装、装备外观和多方向行走。

### 10.3 UI 资产

- 1 套主按钮、次按钮、禁用按钮和图标按钮；
- 1 套大中小面板、页签、弹窗和提示条；
- 12～16 个资源、状态、建筑和操作图标；
- C/B/A/S 四种结果框与对应徽章；
- 进度条、容量条、行动力和倒计时组件；
- 收取、升级、解锁和领取反馈粒子。

## 11. 图片生成与人工整理边界

图片生成适合用于：

- 整体概念图和色彩探索；
- 矿井远景、洞窟和遗迹插画；
- 角色立绘与头像初稿；
- 单体建筑、矿石、工具和装饰物；
- 同一资产的配色或损耗程度变体。

以下内容不直接依赖生成图片完成：

- 带文字和数字的完整 UI 页面；
- 需要严格尺寸的九宫格边框；
- 多帧连续动作和精确 Sprite Sheet；
- 必须无缝拼接的岩层模块；
- 碰撞区域、锚点、点击热区和适配规则；
- 品质角标、进度条填充值等运行时状态。

每张生成资产进入工程前至少检查：

1. 角色服装、工具、手指数和轮廓是否稳定；
2. 透视和光向是否符合统一规范；
3. 是否带有错误文字、伪 UI 或不需要的背景；
4. 透明边缘是否干净，缩小后是否仍可识别；
5. 是否能够拆分锚点并执行预定程序动画；
6. 是否与现有角色、建筑和图标保持同一饱和度与描边粗细。

## 12. 资产规格与命名建议

| 类型 | 建议源尺寸 | 运行时说明 |
| --- | ---: | --- |
| 资源/操作图标 | 256×256 | 常用显示 64～96 逻辑像素，保留透明边距 |
| 角色头像 | 512×512 | 方形构图，脸和标志道具不贴边 |
| 场景小人 | 512×768 内 | 按必要部件拆分，统一脚底和手腕锚点 |
| 远征插画 | 640×360 | 允许卡片裁切，主体避开文字区域 |
| 纵向背景 | 750×1624 的整数倍 | 分层导出，避免单张超大透明图 |
| 九宫格组件 | 按实际组件设计 | 边角不可拉伸区在 FairyGUI 中明确设置 |

建议使用 `ug_` 作为玩法资产前缀，例如：

- `ug_bg_mine_depth_01`
- `ug_building_hoist_stage_02`
- `ug_worker_nora_portrait`
- `ug_icon_ore`
- `ug_expedition_glow_cave`
- `ug_ui_panel_result_a`

最终路径和命名仍应服从项目资源登记与 FairyGUI 包结构，禁止因生成批次另建第二套无登记规则。

## 13. 制作流程

```text
黑白线框与信息层级
  → 一张主界面色彩概念图
  → 确认色板、光向、描边和角色比例
  → 拆分场景、人物、建筑、图标和 UI 组件
  → FairyGUI 页面装配与九宫格设置
  → Cocos 程序动效和粒子
  → 750×1624 Creator 预览
  → 长数字、锁定、满仓、断线等边界状态复核
  → 图集、透明边缘和性能检查
```

资源工作流必须遵守 [客户端开发文档](../CLIENT.md) 中的真源和导出约定：FairyGUI 设计源位于
`apps/art/fairygui`，导出物进入 Cocos resources；客户端代码真源和 Cocos 镜像不得混淆或手工双写。

## 14. 首版明确不做

- 2.5D、等距视角和自由镜头；
- 可自由行走的基地人物；

## 15. 美术验收标准

1. 750×1624 下资源栏、矿井剖面、产率和底栏无重叠或溢出；
2. 玩家在三秒内能找到收取按钮、当前瓶颈和远征入口；
3. 四名矿工在头像和场景小人尺寸下均可凭轮廓区分；
4. 四类建筑的三个外观阶段都能看出成长，但不会改变按钮和岗位位置；
5. 废弃坑道、菌光洞窟和古代遗迹仅凭色彩与轮廓即可区分；
6. 满仓、锁定、行动力不足和可领取不只依赖颜色；
7. 所有运行时数字和中文均为真实文本，不烘焙进图片；
8. 页面关闭、失焦或切后台后循环动画能正确暂停或释放；
9. 项目后续定义的最低规格目标设备上无明显图集抖动、透明边缘黑边或持续掉帧；
10. 关闭粒子和装饰动画后，所有核心状态仍然清晰可读；
11. Creator 真实预览完成安全区、长数字、满仓、锁定、远征中和结果弹窗检查；
12. 参考作品只体现为结构启发，最终资产不存在可识别的临摹角色或界面。
