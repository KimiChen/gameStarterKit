## 0. 结论与事实基线

### 0.1 结论

**Stage3D 定则、Cocos 3.8 定形、消费方定内容。**

| 层 | 给什么 | ⛔ 不给什么 |
| --- | --- | --- |
| 框架（SC0–SC5） | 3D 舞台 `Stage3D`（透视相机 + 3D 根节点 + 层位 + 视口矩形 + 场景全局设置的**租约**）、资源租约 `AssetLease`、纯数学 `logic/scene3d/`（相机装备 / LOD 滞回带 / 分块流式器 / 拾取 / 资产计划）、`EntityPool` / `SkinnedUnits` / `Vfx` 三个机械件、cc 类型桩的 3D 面、资产入库规范与 `verify:assets3d`、`tools/art3d/` 转换骨架、Creator 预览性能证据 | 任何模型 / 贴图 / shader / 特效内容；任何一款游戏的相机手感数值；海面 / 阴影 / 云的具体 EffectAsset |
| kit | 内容包（模型 / 贴图 / 材质 / 动画 / 特效 / Spine）、自写 EffectAsset（海面、领地着色…）、实体表现映射、相机手感与 LOD 阈值常量（kit shared api 面单源）、主城状态机等玩法表现 | 第二套相机 / 层位 / 全局设置写法；第二套资源计数；npm 依赖；改 `scene.scene` / `Main.ts` / `app/**` |
| 插件 | 表现映射（`presentationId → prefab / atlas / anim / sfx`，MMO.md §7.5 `IPresentationMap`）与美术 | 任何渲染代码 |

三个不变判据（贯穿全部阶段）：

1. **kit ⛔ 不碰场景全局**：相机、`Layers`、`SceneGlobals`（skybox / fog / shadows / postSettings）只经 `Stage3D` 租约声明式设置，释放时框架恢复快照。今天 `SlgChunkRenderer.ts:29-31` / `SlgTilemapRenderer.ts:58-60` 直接改 `director.getScene().globals.postSettings.toneMappingType` 并在 dispose 回滚，是 kit 触碰全局的先例，SC3 迁到租约（3D-05）。
2. **每份资源一个持有者**：`AssetLease` 是唯一的 addRef / decRef 边界，页面关闭 = 租约释放 = 引用归零；⛔ 不在 kit 里再写一份 `SlgArtResources`。
3. **纯数学无头可测**：相机装备、LOD 滞回、流式差分、拾取全部在 `logic/`（吃 `logic-purity.test.ts` 纯度门，⛔ 不 import `cc`），`view/` 只做 Node / 组件绑定。

## 3. 目标形态：Stage3D

### 3.1 场景结构（运行时创建，`scene.scene` 零改动）

```text
Scene
├── Canvas（已有）── UI 正交相机（priority 1<<30，clear DEPTH_ONLY，visibility UI_2D|UI_3D）── GRoot / ViewMgr 层容器（base/popup/top）
│                                                    └── kind:"cocos" 页面根（UI_2D 层）：HUD、按钮、面板、slg 2D 地图
└── Stage3D（框架，Main.onLoad → app/bootstrap 创建；⛔ 不序列化进 scene.scene）
    ├── Stage3DCamera：透视，priority 0（先于 UI 绘制），clear SOLID_COLOR 或 SKYBOX（§9.2），visibility = DEFAULT + 框架保留的两个 3D 层位
    ├── Stage3DLight：DirectionalLight（租约可调方向 / 颜色 / 阴影开关）
    └── Stage3DRoot：租约持有者的 3D 内容根（DEFAULT 层）；释放时整树销毁
```

- UI 相机只清深度 / 模板不清颜色（`_clearFlags: 6` 实测），3D 相机先画、UI 后画，HUD 自然叠在世界之上。
- 3D 相机与根节点**运行时创建**：避免 Creator 序列化 diff 与多人铸 uuid 撞车（`Main.ts:34-39` 已记录的 scene 序列化边界），也让无头测试能用 FakeNode 验生命周期。
- 层位：3D 内容只用 `Layers.Enum.DEFAULT`；框架保留两个用户层位给「拾取忽略」「仅相机可见」类需求，由 `stage3dLayers.ts` 常量分配，kit ⛔ 不自设。

### 3.2 租约 API（`apps/client/src/view/scene3d/Stage3D.ts`，框架接缝）

```ts
export interface Stage3DLease {
  readonly root: Node;                          // 内容根（DEFAULT 层）；release 时销毁整树
  readonly camera: Stage3DCameraHandle;         // setPose(position, lookAt) / setFov / setViewport(rectDesignPx) / setClear(color | skybox)
  readonly light: Stage3DLightHandle;           // setDirection / setColor / setShadows(enabled, kind: "planar" | "shadowMap")
  setGlobals(patch: Stage3DGlobalsPatch): void; // skybox / fog / toneMapping / ambient —— 声明式，release 时恢复快照
  screenToRay(xDesignPx: number, yDesignPx: number): RayLike;   // 拾取入口；求交在 logic/scene3d/pickMath.ts
  readonly signal: AbortSignal;                 // 与页面打开世代绑定
  release(): void;                              // 幂等；ViewMgr 关闭路径自动调用
}
export interface Stage3DPort {
  acquire(owner: ViewLifecycleContext, options?: { clearColor?: Color; viewport?: RectDesignPx }): Stage3DLease;   // 忙则抛 Stage3DBusy
  readonly active: boolean;
}
```

- **单租约**：同时只有一个页面持有舞台（第二个 `acquire` 抛 `Stage3DBusy`）；租约随页面 `closeLifecycle` 释放（`ViewBase` 生命周期，`docs/CLIENT.md` §4），页面失败回滚路径同样释放。
- **全局设置快照**：`acquire` 时记录 `SceneGlobals` 现值，`release` 恢复；`setGlobals` 只接受枚举与资源引用，⛔ 不暴露 `globals` 对象。
- **视口**：`setViewport` 接设计像素矩形（页面在 header / footer 之间留出的区域），换算为 `Camera.rect`（归一化）与 aspect；随 GRoot 重建重算（与 `CocosView.mountToLayer`「重挂时重铺」同一语义）。
- **输入**：舞台不接触摸；持有页面（`kind:"cocos"`，`interactive:false`）在自己的 UI 根上收 TOUCH / MOUSE（`SlgMapView.ts:319-327` 形态），把设计像素坐标喂给 `cameraRig` 与 `screenToRay`；HUD 页面在其上层照常拦截（`ViewMgr.ts:281-286` 按 kind 切输入）。
- **无头可测**：`Stage3D` 依赖注入 `{ createNode, addCamera, addLight, sceneGlobals }`，测试用 FakeNode（`cocosPages.test.ts` 同法）验：acquire / release 成对、全局快照恢复、双租约拒绝、页面关闭自动释放、N 次开关后节点数回基线。

### 3.3 与 ViewMgr 的关系

- 持有舞台的页面仍是普通 `kind:"cocos"` 页面（sidecar + `kit.json` 登记 + `codegen:plugins`），⛔ 不新发明 `kind:"3d"`；舞台是页面在 `onOpen` 里 `acquire` 的一份租约，`onCloseLifecycle` 前释放。
- `Stage3DPort` 由 `app/bootstrap` 创建并经与 `gameplay/services.ts` 同形的端口注入给页面（与 `LaunchPort` 同一接缝哲学）；⛔ 不做全局单例 import。

### 5.1 格式与落点

| 项 | 规则 |
| --- | --- |
| 交换格式 | 模型 / 骨骼 / 动画 / 材质参数一律 **glTF 2.0 二进制 `.glb`**（Creator 作者态导入产出 `.mesh` / `.material` / `.animation` / `.prefab` 子资产，`.meta` 随导入生成）；⛔ 不入库 FBX（不可 diff、依赖 FBX SDK）；⛔ 运行时不需要 glTF loader |

### 5.2 `verify:assets3d`（机检，进 `verify:all`）

对 `apps/Cocos/assets/resources/{kits,plugins}/*/3d/**` 逐文件：扩展名白名单（glb / png / effect / prefab / json / atlas / skel）；每个文件有 `.meta` 且 `importer` 与扩展名匹配（glb → `gltf`，png → `image`，effect → `effect`）；体积不超配置；`.glb` 头魔数与 chunk 长度合法；`art3d.config.json` 存在且引用的文件都在。
变异验证：把一张 png 改名为 `.jpg` → 白名单转红；删一个 `.meta` → 转红；配置上限调小 → 体积转红。

### 5.3 `tools/art3d/`（框架骨架，消费方配置）

照 `tools/slg-maps/` 形态：venv（UnityPy / pygltflib / pillow / numpy）+ `art3d.config.json`（每个 kit 一份，放 `apps/kits/<id>/art/3d/`）+ 分步脚本 + 往返自检：

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| `extract.py` | Unity AssetBundle（消费方在 config 指路径） | Mesh / Texture2D / Material 参数 / AnimationClip / Avatar 的中间 JSON + 原始二进制 |
| `to-gltf.py` | 中间产物 | `.glb`（网格 + 骨骼 + 蒙皮 + 动画轨；材质只带 PBR 参数与贴图槽映射，⛔ 不带 shader） |
| `textures.py` | Texture2D（含 ASTC / ETC2） | png（解压、翻转、sRGB 标记） |
| `material-map.py` | Unity shader 名 + 参数 | 到消费方 EffectAsset 的**手工映射表**校验（缺映射即报错，⛔ 不自动转 shader） |
