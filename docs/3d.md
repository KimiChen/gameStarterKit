## 0. 结论与事实基线

### 0.1 结论

**Stage3D 定则、Cocos 3.8 定形、消费方定内容。**

| 层 | 给什么 | ⛔ 不给什么 |
| --- | --- | --- |
| 框架（SC0–SC5） | 3D 舞台 `Stage3D`（透视相机 + 3D 根节点 + 层位 + 视口矩形 + 场景全局设置的**租约**）、资源租约 `AssetLease`、纯数学 `logic/scene3d/`（相机装备 / LOD 滞回带 / 分块流式器 / 拾取 / 资产计划）、`EntityPool` / `SkinnedUnits` / `Vfx` 三个机械件、cc 类型桩的 3D 面、资产入库规范与 `verify:assets3d`、`tools/art3d/` 转换骨架、Creator 预览性能证据 | 任何模型 / 贴图 / shader / 特效内容；任何一款游戏的相机手感数值；海面 / 阴影 / 云的具体 EffectAsset |
| kit | 内容包（模型 / 贴图 / 材质 / 动画 / 特效 / Spine）、自写 EffectAsset（海面、领地着色…）、实体表现映射、相机手感与 LOD 阈值常量（kit shared api 面单源）、主城状态机等玩法表现 | 第二套相机 / 层位 / 全局设置写法；第二套资源计数；npm 依赖；改 `scene.scene` / `Main.ts` / `app/**` |
| 插件 | 表现映射（`presentationId → prefab / atlas / anim / sfx`，MMO.md §7.5 `IPresentationMap`）与美术 | 任何渲染代码 |

四个不变判据（贯穿全部阶段）：

1. **kit ⛔ 不碰场景全局**：相机、`Layers`、`SceneGlobals`（skybox / fog / shadows / postSettings）只经 `Stage3D` 租约声明式设置；舞台与独立全局租约共用 token 覆盖表，释放时按基线和仍有效的 patch 重算（§3.2）。今天 `SlgChunkRenderer.ts:29-31` / `SlgTilemapRenderer.ts:58-60` 直接改 `director.getScene().globals.postSettings.toneMappingType` 并在 dispose 回滚，是 kit 触碰全局的先例，SC3 迁到租约（3D-05）。
2. **每次持有都有租约**：`AssetLease` 是唯一的 addRef / decRef 边界，页面关闭归还本页全部引用；仍有效的全局 token / 其他页面可保留自己的持有；⛔ 不在 kit 里再写一份 `SlgArtResources`。
3. **纯数学无头可测**：相机装备、LOD 滞回、流式差分、拾取全部在 `logic/`（吃 `logic-purity.test.ts` 纯度门，⛔ 不 import `cc`），`view/` 只做 Node / 组件绑定。
4. **静态先离线、运行时只做选择**（Cyberpunk 校正）：LOD 变体、静态合批、光照与反射探针一律离线产出为资产；运行时只按画质档 × 视口**选择**加载哪些资产，⛔ 运行时合并网格、⛔ 逐物体 `LODGroup`、⛔ 实时阴影为缺省（[3D-ASSETS.md](3D-ASSETS.md) §0 / §7）。

## 3. 目标形态：Stage3D

### 3.1 场景结构（运行时创建，`scene.scene` 零改动）

```text
Scene
├── Canvas（已有）── UI 正交相机（priority 1<<30，clear DEPTH_ONLY，visibility UI_2D|UI_3D）── GRoot / ViewMgr 层容器（base/popup/top）
│                                                    └── kind:"cocos" 页面根（UI_2D 层）：HUD、按钮、面板、slg 2D 地图
└── Stage3D（框架，Main.onLoad → app/bootstrap 创建；⛔ 不序列化进 scene.scene）
    ├── Stage3DCamera：透视，priority 0（先于 UI 绘制），clear SOLID_COLOR 或 SKYBOX（§9.2），visibility = DEFAULT | STAGE3D_OVERLAY（排除 HIDDEN）
    ├── Stage3DLight：DirectionalLight（租约可调方向 / 颜色 / 阴影开关）
    └── Stage3DRoot：租约持有者的 3D 内容根（DEFAULT 层）；释放时整树销毁
```

- UI 相机只清深度 / 模板不清颜色（`_clearFlags: 6` 实测），3D 相机先画、UI 后画，HUD 自然叠在世界之上。
- 3D 相机与根节点**运行时创建**：避免 Creator 序列化 diff 与多人铸 uuid 撞车（`Main.ts:34-39` 已记录的 scene 序列化边界），也让无头测试能用 FakeNode 验生命周期。
- 层位：3D 内容只用 `Layers.Enum.DEFAULT`；框架保留两个用户层位（`STAGE3D_HIDDEN` 不绘制 / 不拾取，`STAGE3D_OVERLAY` 仅相机可见 / 不拾取）——用户层位必须在 `apps/Cocos/settings/v2/packages/project.json` 的 `layer` 数组声明（Cyberpunk 的 `FPS / MOTION / RENDER-ID` 同法），`stage3dLayers.ts` 常量与之钉死并由测试比对；kit ⛔ 不自设。3.8.8 的配置 `value` 与 `Node.layer` 都是位掩码（HIDDEN=1、OVERLAY=2），`Layers.nameToLayer` 则返回位索引，不能直接混用；相机掩码沿 SC0 已验实现为 DEFAULT | OVERLAY。

### 3.2 租约 API（`apps/client/src/view/scene3d/Stage3D.ts`，框架接缝）

```ts
/** 租约持有者的最小接口：`ViewLifecycleContext` 直接满足；gameplay 世界用 route signal + `GameplayInstanceHost.generation` 适配（3D-34）。 */
export interface Stage3DOwner { readonly signal: AbortSignal; isActive(): boolean; }

export interface Stage3DLease {
  readonly root: Node;                          // 内容根（DEFAULT 层）；release 时销毁整树
  readonly camera: Stage3DCameraHandle;         // setPose(position, lookAt) / setFov / setViewport(rectDesignPx) / setClear(color | skybox)
  readonly light: Stage3DLightHandle;           // setDirection / setColor / setShadows(enabled, kind: "planar" | "shadowMap")
  setGlobals(patch: Stage3DGlobalsPatch): void; // 整份替换本舞台 token 的 patch；释放时移除此 token 并重算
  screenToRay(xDesignPx: number, yDesignPx: number): RayLike;   // 拾取入口；求交在 logic/scene3d/pickMath.ts
  readonly signal: AbortSignal;                 // 与 owner 的 signal 绑定（页面打开世代或 gameplay 实例）
  release(): void;                              // 幂等；owner 失效（ViewMgr 关闭 / gameplay 结束）自动调用
}
export interface Stage3DPort {
  acquire(owner: Stage3DOwner, options?: { clearColor?: Color; viewport?: RectDesignPx }): Stage3DLease;   // 忙则抛 Stage3DBusy
  acquireGlobals(owner: Stage3DOwner, patch: Stage3DGlobalsPatch): { release(): void }; // 与舞台共用覆盖表，可乱序释放（3D-17）
  readonly quality: QualityProfile;                                 // low | medium | high + 特性开关（§4 quality.ts），只读
  readonly active: boolean;
}
```

- **单舞台租约**：同时只有一个页面持有舞台（第二个 `acquire` 抛 `Stage3DBusy`）；多个独立全局租约可与它并存。`acquire` / `acquireGlobals` 都要求有效的 `Stage3DOwner`（页面打开世代，或 gameplay 实例的 route signal + generation）；订阅 `owner.signal`，关闭、打开失败回滚、场景销毁、permanent 页重开、gameplay 结束均自动幂等释放，已失效 owner 不得继续设置或取得租约。
- **统一全局覆盖表**：首个 token 取得时保存框架管理字段的基线；舞台也注册一个初始为空的 token，⛔ 另存一份舞台快照并在关闭时直接写回。每份 token 有单调递增的取得顺序；每次新增、更新、释放，均从基线开始，按取得顺序逐字段应用仍有效的 patch。后取得的 token 只覆盖自己声明的字段；`setGlobals` 整份替换该舞台 token 的 patch（省略字段表示撤回该字段覆盖），不改变顺序。最后 token 释放才恢复完整基线并清空覆盖表。例如基线 A → 舞台 B → 独立租约 C，先关舞台仍为 C，再关 C 回 A；反向先关 C 回 B，再关舞台回 A，⛔ 复活失效的 B。
- **全局资源持有**：patch 只接收已加载且调用方仍持有的资源引用和枚举 / 数值，`setGlobals` 不做异步加载，⛔ 暴露 `globals` 可变对象；覆盖表经同一个 `AssetLease` 引用边界持有基线及每个有效 patch 引用的资源，即使 patch 暂时被更高 token 遮挡也不提前释放。替换先取得新资源引用，校验 / 应用成功后释放旧引用；失败回滚时旧 patch 和引用保持有效。释放 token 时先重算并应用新状态，再归还移除 token 的引用；最后一次释放先恢复基线，再释放基线的额外持有。**分期（3D-43 修正 3D-36）**：SC1 的 `Stage3DGlobalsPatch` 仍只含枚举 / 数值字段（toneMapping / fog / ambient / shadows 参数）；SC1-B2 在 `AssetLease.ts` 交付内部 loaded-asset retainer 接口、真实同步实现与 FakeRetainer 测试，由 SC1-B4 临时框架 loader 使用，成功与迟到回调均经此唯一边界成对持有 / 归还。完整异步批量加载、超时 / 取消归 SC3-B1；SC3-B4 接入 `skybox.enabled / envmap / diffuseMap / reflectionMap / lighting`（`lighting` 为 hemisphere / reflection / diffuse），基线与每份 patch 独立持有、同一 patch 内按资源身份去重；真实适配器按 Creator 3.8.8 的 envmap setter 副作用恢复反射 / 漫反射图及光照模式。只管理当前 HDR/LDR 槽，HDR 模式仍为项目设置。应用与回滚同时失败时，候选资源也保留至完整重放或场景销毁；两份夹具临时加载路径及 SLG 均迁移到正式 AssetLease。SC3 复用该 retainer，不再建立第二套计数。不新增 kit 公开 retain API；kit 无权裸调 `addRef` / `decRef`。
- **所有全局写入共用此边界**：舞台 `setGlobals`、`light.setShadows` 涉及的 `SceneGlobals.shadows` 字段、skybox / toneMapping 等全部进入该舞台 token；相机 / 灯组件私有字段仍随舞台销毁。slg 两处 `postSettings` 直改在 SC3 迁为 `acquireGlobals(owner, patch)`，与舞台交错关闭也不串状态。
- **视口**：`setViewport` 接设计像素矩形（页面在 header / footer 之间留出的区域），换算为 `Camera.rect`（归一化）与 aspect；随 GRoot 重建重算（与 `CocosView.mountToLayer`「重挂时重铺」同一语义）。
- **输入**：舞台不接触摸；持有页面仍为 `kind:"cocos"`、`interactive:false`，在自身 UI 根接收被框架输入路由判给世界的 TOUCH / MOUSE，将设计像素坐标送给 `cameraRig` / `screenToRay`。可点击 FGUI HUD 使用 §3.3 的 overlay 接缝（SC1-B9 已交付）。世界有**两种载体**（3D-33）：ViewMgr 的 `kind:"cocos"` 页通过 `CocosView.subscribeRawInput` 订阅，gameplay presentation 通过 `GameplayPresentationHost.rawInput` 订阅（Snake / BallMove 已迁移）；两者绑定 owner 的 signal / isActive，在玩法 router 前执行同一归属与取消机制。
- **无头可测**：`Stage3D` 依赖注入 `{ createNode, addCamera, addLight, sceneGlobals }`，测试用 FakeNode（`cocosPages.test.ts` 同法）验：acquire / release 成对、两种相反顺序及多 token 乱序释放、被遮挡 patch 更新后再显现、字段独立覆盖 / 撤回、重复释放、资源替换与失败回滚、双舞台拒绝、owner 失效自动释放、N 次开关后节点数与引用数回基线。

### 3.3 与 ViewMgr 的关系

- 持有舞台的页面仍是普通 `kind:"cocos"` 页面（sidecar + `kit.json` 登记 + `codegen:plugins`），⛔ 不新发明 `kind:"3d"`；舞台是页面在 `onOpen` 里 `acquire` 的一份租约，由打开世代取消自动释放；页面显式提前 release 也幂等。
- `Stage3DPort` 是 `AppPorts` 的一个字段（`app/ports.ts` `stage3d`），由 `app/bootstrap` 创建注入；kit / 插件页面经 `PluginInstallContext.ports.stage3d` 取得（slg 取 `ports.session / lobbyRpc` 的同一入口）；⛔ 不做全局单例 import。
- **两个入口（3D-34，部分修正 3D-13）**：gameplay 模块拿不到 `AppPorts`，经 `GameplayServicesContext.stage3d`（`gameplay/services.ts`，已在 gameplayFlow 保护面）取得**同一个** `Stage3D` 实例；owner 由 `GameplayInstanceHost` 的 route signal + generation 适配为 `Stage3DOwner`。`services.ts` 只是第二个入口，⛔ 不是第二份实现。
- **非模态 HUD 是框架新增能力（SC0 原型、SC1-B9 固化）**：`ViewMeta` / `.view.json` 新增可选**三态** `inputMode: "modal" | "overlay" | "passive"`（3D-39）：`modal` = 现 `interactive:true` 语义（建立模态边界）、`passive` = 现 `interactive:false`（不参与命中）、`overlay` = 参与命中但不建立边界、不暂停下层；`interactive` 保留为兼容别名（true ⇒ modal、false ⇒ passive），同时给出且矛盾由 sidecar schema / codegen 拒绝；`overlay` 只允许 `kind:"fgui"`。最高 `modal` 页面才建立模态边界：其下全部页面停用输入，边界以上按显示顺序参与命中；overlay 自身不暂停下层 Cocos 页。没有模态页时，HUD 与世界共同可交互。
- **命中与一整次手势归属**：overlay 的挂载槽及 HUD 空白容器必须 `opaque:false`，装饰对象 `touchable:false`，只有声明可交互的控件 / 区域吃输入。`FguiView` 的框架输入适配负责按 pointer 开始位置固定 HUD / 世界归属，直至 end / cancel；HUD 上按下拖出不得拖地图，地图上按下移入 HUD 仍完成原拖拽；wheel 按当前命中路由。锁定 FairyGUI 的 `InputProcessor` 已有 `target === GRoot` 时 `preventSwallow` 的空白穿透分支，但 move / end 会重新命中，⛔ 仅改 slot.opaque 或 FGUI 总开关便声称完整解决。适配集中在框架 View 层、⛔ 修改 vendor，机制须经 SC0 真引擎证明。
- **模态与生命周期**：打开模态弹窗即取消下层 HUD / 世界的在途按压并阻断输入；关闭后重算并恢复 HUD 与地图，⛔ 补发 click 或续接旧拖拽。HUD 关闭、页面失败回滚、置顶、GRoot 重建同样清理 pointer 归属。`ViewMgr` 负责边界 / 挂载槽 / 输入重算，`FguiView` 负责 FGUI 命中适配与取消，`CocosView` 负责世界页暂停 / 恢复及手势取消桥接；数学校准仍归 `logic/scene3d`。
- **gameplay 原始输入分流（3D-41 修正 3D-33）**：`GameplayPresentationHost.dispatchInput` / `GameplayInstanceHost.dispatchInput` 已是业务意图入口，⛔ 在这里反推 pointer 归属。SC1-B9 增框架原始输入订阅端口，经 `GameplayServicesContext` / presentation host 注入；事件带 pointer ID、阶段与设计像素坐标，wheel 单独按命中分流，订阅随 owner 世代释放。框架在玩法 router 处理前固定 HUD / 世界归属，仅将获准事件交世界；现有全局 `input.on` 的 presentation（至少 snake 验收载体）同批迁移，玩法只消费事件与 cancel 回调，不各自判断 HUD 区域。HUD 主动产生的技能等业务意图仍可经正常 dispatch 通道发送，⛔ 一概屏蔽 HUD 的业务动作。
- **取消与并行指针**：模态抢占、页面关闭 / 重挂、宿主 hide 时，框架先对世界已获准指针发取消并清理 router 的占用、摇杆 / boost 状态，再阻断新触摸；动作停止须有明确清理路径，⛔ 让普通输入闸吞掉必要的 `release-boost`。恢复只接受新手势。验收必须含「一指世界摇杆 + 另一指 HUD」「按住 boost 打开模态」「跨 HUD 边界后结束 / 取消」，除意图外同时断言本地控制状态复位。HUD 画在世界节点内的既有退路仍可用，升级 overlay 才接此端口。

`CameraRig` 在二维移动平面上工作，输入是视口中心为原点的设计像素。消费方提供相对中心的投影偏移，
允许屏幕坐标和 zoom 的非线性换算；平移使用手指或双指中点起终点的投影差，保持锚点。仿射适配器可注入
等价的 `panOffset`，让 SLG 保留原运算顺序。边界按当前投影视口半范围钳制，视口大于世界的轴固定居中；
投影求交可消费 `pickMath`。手感参数由消费方注入，SLG 保留原值与状态化
LOD。`follow(target)` 保留目标点引用，立即定位并在每个有效 `step(dt)` 读取最新坐标，不平滑、不改变
zoom、不置 `touched`；非法目标采样保留上次有效位置。`follow(null)`、`cancel()`、手动手势或 `locate`
退出跟随，进入跟随会清掉旧指针和惯性；页面/玩法退出调用 `cancel()` 释放目标引用。

`ChunkStreamer` 接收含边界的世界格矩形；消费方注入地图宽高、chunk 边长、数值 key 与其逆解码，
`margin` / `retainMargin` 都是从视口起算的世界格外扩量。队列按距加载矩形中心的方形环扩张，
同环按数值 key 升序；批请求只合并队列中的完整矩形，最多 2×2 块。加载矩形变化或 `reset()`
才推进代次，旧代次完成即使与新请求同 key 也拒收；加载矩形不变时保留带与在途请求保持原状。
`reject` 不自动重排，`defer` 回队首且重试时间由调用方负责；保留带内已加载的块不重复请求。
SLG 薄包装保留 16 格边长、4 格加载外扩与 20 格保留外扩。

`pickMath` 接收结构化 `{ origin, direction }` 射线与 `{ min, max }` AABB，返回
`{ t, point } | null`；`point = origin + t * direction`，方向无需归一化，只有单位方向的
`t` 才是距离。只接受前向交点（`t >= 0`）；平面平行（含共面无唯一交点）返回 `null`。
AABB 视为闭合实体，起点在内部或表面返回 `t = 0`，擦边与零厚度盒算命中，平行轴显式判区间。
非法数值、零方向、反序边界及不可表示的命中抛 `RangeError`；函数不改输入、不引入引擎依赖。
`unprojectDesignPx(x, y, lease.screenToRay, height = 0)` 组合舞台射线与水平面求交，输入为
**左下原点的绝对设计像素**；舞台内部继续由 `viewport.ts` 处理留黑边 / 局部视口 / 缩放，
消费方不直接传 `Camera.screenPointToRay`、不重复换算、不翻转 Y。越界拖拽坐标保持外推，
每次取当前舞台射线，不缓存视口或相机矩阵；舞台失效异常原样向调用方传播。

`EntityPool` 与 `AssetPlan` 通过同一 `AssetCatalog` 选择层和显式预制变体；detail-layers.json 中可选的
`hideAtLod` 表（`{ prefab: { bundle, path }, lod }[]`） 表示此档及更远不加载、不激活。pool capacity 限制每个表项的逻辑实体数与跨变体
active + inactive 节点数；隐藏实体保留逻辑名额，降档超额时保留最早请求。每帧预算在整个池实例内共享，
失败激活也计数，同帧重复 step 不重置额度。取消采用请求身份隔离，迟到加载只能归还租约。
despawn 留下可复用节点，显式 evict / 不兼容切档 / close 先销毁节点，再经 Cocos 帧末退休归还资产；
同一源材质按 instancing 模式共享池内副本，不修改源资产。静态池不复用 SC4 的蒙皮 / 特效容量政策。

⛔ 框架段任何提交不得出现 `apps/kits/lvr/`、海面 / 城建等内容词；夹具只用灰盒（同 MMO.md §5.1 夹具纪律）。

## 7. 验收与证据

- **机检（进 `verify:all`）**：`logic/scene3d` 无头测试；`Stage3D` / `AssetLease` FakeNode 生命周期测试；`verify:assets3d`；`logic-purity`（`logic/scene3d/**` 自动受门）；`serverImportBan`；protected-paths 无侵入矩阵；两套 typecheck 探针。
- **Creator 证据（⛔ 不进自动聚合门禁，仍是所列阶段的人工退出条件）**：`stage3dFixture` 剧本——打开 → HUD 点击 / 空白拖世界 / 拖拽跨 HUD 边界 / 双指分别操作 HUD 与世界 / 缩放 / 拾取 → 按住 boost 打开模态并清理控制状态 → 关闭模态只接受新手势 → 页面关闭 ×20，落盘截图 + `report.json`（console 空、节点 / 业务引用回基线、预热后 GFX 无持续增长）+ `--perf` 段（原始帧间隔 p50 / p95 / max、draw call、三角数、GFX 内存），目录 `docs/evidence/creator-<date>/stage3d/`（按 .gitignore 不入库，README 摘要入库）。
- **帧时口径（3D-45）**：SC0 探针与 SC3 `--perf` 共用口径：注入固定帧回调，连续保存 `performance.now()` 差分毫秒与自身递增序号，设备计数器在帧末读取并标明采样时点；`root.frameTime × 1000` 只作游戏 dt 辅助字段，⛔ 称为 GPU 耗时，⛔ 用每秒归零的 `root.frameCount` 作累计序号。预热 60 帧后采 240 帧；加载 / 首次激活另记录原始序列与最大间隔，不被预热窗口抹掉；>1 s 间隔必须保留。报告标注设备、平台、WebGL 版本、画质与页面可见状态；前后台切换污染样本则标记该次无效并重跑，不静默剔除长帧。聚合用例须证明 1.2 s 间隔仍为 1200 ms，不能被引擎回填的约 16.7 ms 代替。
- **内存基线**：先完整加载 / 关闭一次并等待引擎延迟销毁稳定，再记录预热基线；之后 20 次开关须节点与业务资产引用归零，GFX 内存无持续增长。骨骼贴图池等引擎保留缓存须登记预热前后值和持有原因，不能把所有高水位都认作泄漏，也不能用“引擎缓存”掩盖逐次增长；需要释放全池时只由框架统一生命周期处理。
- **真机验收（3D-47）**：SC4-B3 须附真实微信 low 档、远程 bundle 冷缓存加载、缓存满 / 写入失败 / LRU、退出重启后命中或重新下载的证据与判定；必须实际进入缓存写入失败 / LRU 分支，并记录容量限制与触发方式。预期写入失败须按引擎策略完成临时加载 / 淘汰恢复，未淘汰同版本资源重启应命中，已淘汰或版本变更允许重下；意外加载失败、悬挂或无恢复的重复下载不得通过。平台、基础库版本、设备、缓存状态和资源版本均记录。Chrome WebGL1 提供渲染兼容证据；lvr A3 的真机缓存验收执行同一口径。
- **变异验证**：改回各租约独立恢复快照或保留已释放 token → 「乱序释放恢复失效 patch」转红；去掉全局资源 retain → 「遮挡后恢复资源失效」转红；overlay 改为 opaque 或当 modal → 「HUD 与世界共存」转红；原始分流退回意图入口 → 「HUD 指针抢世界 router / 双指并行」转红；删双租约判定 → 转红；`AssetLease` 失败分支不 release → 「迟到完成引用泄漏」转红；`lodBands` 去掉滞回 → 「阈值附近抖动」转红；`verify-assets3d` 白名单加 `.jpg` → 夹具反例转红；放过缺失 / 越权 UUID → 干净安装反例转红；蒙皮取消骨骼贴图分批或实时路径启 instancing → 多 clip / 跨贴图反例转红；帧时改用游戏 dt → 长帧保留用例转红。
