## 1. 已确认的目标

1. **服务端是唯一主交付物。** 新服务端直接提供新的 WebSocket Lobby 入口，并独立完成协议校验、鉴权、路由、幂等、推送、多进程转发、持久化与运行验证；客户端不是本计划的产品交付面。
2. 为证明兼容性，测试客户端必须同时具备连接旧 `apps/server`（本目录的 `../server`）Colyseus Lobby 与新原生 Lobby 的最小能力。新通道不要求复刻 Colyseus matchmaking、Room 帧或重连 token 格式，但不能替换或破坏旧通道；这项要求只约束 transport 与协议行为，不扩展为客户端 UI 建设。
3. 保留现有 Lobby **业务协议**：字符串路由、请求与响应信封、业务字段含义、字符串错误码、推送，以及幂等语义；允许按共享契约规则扩展。
4. 彻底移除活动运行、构建和生成链中的 Protobuf，不保留内部 Protobuf，也不增加“新入口 → 数字协议号 → Protobuf”的转换层。
5. 内部调用按字符串路由和类型化对象执行；复用有价值的 Action、ServerTask、调度、锁、事务、Bean 持久化及提交后回调能力。
6. 其他实现可以调整，但必须给出可验证的行为和迁移结果，不能以空实现、默认成功或吞错作为兼容完成的证据。
7. 同一份**最小测试客户端/transport 代码**必须支持两种服务端，由明确配置选择 Lobby transport；缺少新通道配置时保持原 Colyseus 行为。shared 只允许兼容性新增，不得要求旧服务端同步升级才能继续使用。除非服务端协议无法通过更低成本的测试证明，否则不增加客户端产品功能。

“保留之前的协议”指 [协议兼容.md](协议兼容.md) 中现有客户端的 Lobby 业务契约，**不指旧 Protobuf 协议、数字协议号或旧二进制包头**。

原文档中的协议真源和业务语义可作为检查索引；其中“保留内部 Protobuf”“旁挂 Colyseus 兼容网关”“客户端完全不改”等建议已被本次决策替代。具体字段和校验规则以当前 `apps/shared` 源码为准。例如，当前 `user.getInfo` 的 `user` 必须存在，不能沿用原文档中的 `user: null` 示例。

## 2. 范围和完成边界

### 本次纳入

- `engine/`：客户端连接与调用抽象、协议注册、错误返回、推送、Bean 与 Protobuf 的耦合。
- `server/`：启动装配、鉴权、业务路由、协议生成、多进程请求转发、调试工具和相关检查。
- `apps/shared`：复用已有 Lobby 契约，独立增加新通道的传输与连接控制契约；保持旧导出、校验器和版本语义可用。
- `apps/client`（**测试支撑范围，不是产品建设范围**）：只保留验证所需的 Colyseus/native transport、显式选择机制，以及 `rpc`、`rpcIdem`、`onPush`、连接生命周期的最小兼容接口。默认优先使用 Node/ws 驱动和现有客户端模块测试；仅当这些测试无法证明真实引擎边界时，才运行已有 Creator GUI 驱动，且不为此扩展页面或重做 UI。
- 对应生成物、同步镜像、测试、依赖锁文件和维护文档；客户端生成物与镜像只处理本次最小接入实际触达的部分。

### 不自动纳入

- 不迁移实时 GameRoom、玩法状态同步和玩法 C2S/S2C。
- **不做客户端 UI 建设**：不迁移或统一 UniFlex / FairyGUI / 手写 Cocos 页面，不做视觉还原、页面重构、动效、交互打磨、UI 资源生产或客户端架构清理；既有 GUI 驱动只作为一次性黑盒证据复用。若服务端变更意外暴露客户端 transport 缺陷，只修阻断协议验证的最小问题并补回归测试，不顺势扩大范围。
- 不把客户端全量 `typecheck`、全量 UI 测试或 Creator `.meta` 清理作为服务端完成条件；只要求本次触达的 transport/协议测试通过，并如实记录既有客户端红灯。
- 不删除或为新通道改造旧 `apps/server`；旧服务端及其 Lobby 客户端链路必须继续可用。不重写无关业务，不清库或重新分配持久化字段编号。
- 不读取或清理 `server/module-library/` 归档载荷；需要处理时另行按其 AGENTS 规则定位和执行。
- 不恢复嵌套 `.git`，不扩展到无关的构建、部署或运行环境修复。
- 不以修改正式区服目录、发布或切流作为本地开发的默认步骤。

“彻底移除 Protobuf”的验收范围是此次迁移的活动源码、公开入口、依赖、构建、生成及测试链；归档载荷和 Git 历史不属于清理对象。需要防止未迁移的归档模块被直接恢复进新的活动链。

## 3. 目标结构与所有权

```text
最小测试客户端 / Lobby API（rpc / rpcIdem / onPush）
  ├─ 兼容基线：默认旧配置 → 现有 Colyseus transport → apps/server
  └─ 被测目标：显式新配置 → 原生 WebSocket transport → apps/serverNew
```

上图是**测试拓扑**，不是双客户端产品路线图。长期所有权集中在 `apps/serverNew/{engine,server}`；客户端只提供足以比较两条服务端链路的探针，不因本计划继续扩展页面、资源或 UI 框架。

新服务端内部链路：

```text
原生 WebSocket transport
  → shared 传输信封与业务契约校验
  → 连接鉴权 / 会话复验 / 限流 / 幂等
  → 字符串路由对应的业务 Action
  → ServerTask / Bean / 数据持久化
  → 提交成功后的响应与领域推送
  → shared 响应校验 → WebSocket
```

- `engine` 提供通用连接、执行和注册能力，不导入具体游戏域或复制业务契约。
- `server/src/runtime/` 承载共享执行机制，`server/src/startup/` 负责装配；业务 handler 和数据转换归 `server/src/modules/<module>/`。
- shared 是 wire 类型、路由、错误码和 runtime validator 的唯一真源；生成注册表仍由原有登记源生成，禁止手改。
- 内部调用无须序列化后再反序列化；跨进程传输可选择明确、可验证的对象编码，不使用 Protobuf，也不假定它等同于客户端帧格式。
- transport 与端点在连接建立前由可信配置确定；连接 ownership 必须包含通道类型和端点，切换时清理旧连接与 pending。禁止通过认证失败、超时或业务错误自动改连另一套服务端，更不能跨服务端重放写请求。

## 4. 协议必须保持的语义

### 4.1 业务契约

- 请求保留 `{ id, type, payload? }`；成功响应保留 `{ id, ok: true, data? }`；失败响应保留 `{ id, ok: false, err: { code, msg } }`。
- 推送保留 `{ type, data }`；新增传输层外壳可以区分 RPC、push 和控制消息，但不能改变内层业务信封含义。
- 路由、req/res 类型、执行模式和 validator 从 shared 读取，不能照抄文档中的固定路由清单维护第二份真源。
- 请求及响应均严格校验；未知字段不得先剔除后执行。未知路由返回 `UNKNOWN_TYPE`，服务端非法响应返回 `INTERNAL`。
- 新通道扩展使用独立外层 validator 和传输版本，不给旧 Colyseus join/RPC 添加其不接受的字段，也不为新通道单独增加而提升旧 Lobby 的准入版本。涉及公共业务契约的扩展必须同时证明旧服务端和旧通道兼容；破坏性变更不属于本次授权。不能直接给旧响应自动附加 `_mod` 等未声明字段。

### 4.2 鉴权与身份

- 新 WebSocket 需要显式的鉴权/ready 流程；鉴权完成前不允许执行业务 RPC。
- 浏览器与 Cocos WebSocket 不依赖可自定义 HTTP Authorization header；默认采用建连后的认证控制消息，token 不进入 URL 或日志。
- token 通过既有身份服务契约验证；uid、区服和授权状态来自可信上下文，不能被业务 payload 覆盖。
- 新框架数字 uid 与 shared 字符串 uid 必须有明确关联方案；禁止用 `Number(uid)` 假定可转换，禁止丢失精度或发生身份碰撞。
- 保留每消息会话复验、封禁/撤销/顶号后的失效行为。内部业务数字错误可按需保留，但 wire 错误必须是 shared 合法字符串码。

### 4.3 幂等与连接生命周期

- RPC `id` 仅用于请求配对，不替代业务 `clientReqId`。
- 幂等身份至少绑定 uid、sId、route 和 clientReqId；同 ID 不同 payload 必须冲突，同一请求不能重复产生副作用。
- 保留执行中、结果过期及领域查询恢复语义；超时不等于底层写入已取消。
- 断线后结算 pending RPC，拒绝离线发送，不自动重放写请求；业务重试复用原 clientReqId。
- 重连必须复验身份；凭据不能跨 uid/sId 使用，旧连接的迟到回调不能覆盖新会话。
- 默认沿用原有可观察时限：RPC 15 秒、handler 10 秒、消息上限 64 KiB、限流容量 20/补充 10 每秒、重连宽限 10 秒。调整时说明原因并测试客户端行为。
- 强制下线保留 `auth.forceLogout` 和 4901/4902/4903 关闭语义；生产 `INTERNAL` 不泄露内部信息。
