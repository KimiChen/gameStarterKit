## P5：同步迁移多进程路径（协议模块调整.md）

### 实现

- `MultiProcessRuntime` 删除旧 PB 客户端原始包重放：不再 `encodeRoutedPacket`/`decodeRoutedPacket`、
  不再 `createDetachedConnection` + 在目标 worker 重放客户端帧。`ClientServer.receive/onMessage`、
  `BaseCall.sourceData`、`ClientApiCall` 的 `sourceData`/`routedBindId` 一并移除。

  + traceId/invokeLayer；结果以对象回传。`normalizeProcessPipeFailure` 保证字符串错误码原样回传，

## P3：新入口真实闭环（2026-09-18）

### 修掉的真实缺陷（不是补测试，是补实现）

`server/src/runtime/identity/NativeLobbyAuthProvider.ts` 原先在 `authenticate` 里把**客户端 auth 帧里的 `sId`**
原样送去平台验票，进程级 `SERVER_ID` 完全不参与判断。后果：持 zone 9 合法票据的客户端可以在 zone 1 进程上
建连并落他区角色与内部 uid（身份服务会为「他区票据」返回合法结果）。修法：

- 构造改为 options 对象，`serverId` **必填**，构造期 `!Number.isSafeInteger(serverId) || serverId < 1` 直接抛
  `native Lobby auth requires a fixed server id`（缺省即 fail-open，必须在构造期拒绝）。
- `authenticate()` 首行加 `if (input.sId !== this.serverId) throw new LobbyAuthRejection({ code: 'AUTH_REQUIRED', msg: '区服不匹配' })`，
  位置必须在 `verifier.verify` **之前**。
- `startup/NativeLobbyRuntime.ts` 传 `serverId: SERVER_ID`；`test/runtime/protocol/native-lobby.test.ts` 3 处构造改 options 形式。

### 新增真实 WebSocket 端到端测试

`server/test/runtime/protocol/native-lobby-e2e.test.ts`，**走生产装配路径** `startConfiguredNativeLobby()`：

- **客户端空请求体必须发 `payload: {}`**：shared 的 `emptyPayload` 走 `rpcRecord()`，缺省 `payload` 会得

### 新踩的坑

- `engine test:lobby`（`test/direct/lobbyServer.test.ts`）原本有**两处测试自身竞态**，表现为随机失败，
  极易被误判成「CPU 抢占导致的计时抖动」：
  1. `message()` 用 `socket.once('message')`。封号路径背靠背发 `push` + `auth.error`，两条帧可能落在同一次
     TCP 读里、在同一个 tick 内连续 emit；第二条到达时 `once` 监听器已被移除 → 帧被直接丢弃 →
     随机 `message timeout`（实测 1/15）。改成按 socket 顺序排队的收件箱（wire 测试必须保序）。
  2. 末尾 `releases.length === 1` 只等一个 `setTimeout(…, 0)`；客户端观察到 close 不等于服务端 `close`
     回调已执行完 → 随机 `0 !== 1`（实测 1/20）。改成 `waitFor(() => releases.length >= 1)` 再断言，
     断言强度（恰好一次）不变。修后连跑 25 次 0 失败。
  教训：随机失败的计时测试，先用**调用点栈**定位到具体哪一次等待超时（把 `new Error().stack` 塞进 timeout
  错误里），再判断是环境问题还是测试自身；不要一句「CPU 抢占」就放过。
- 用 python heredoc 做「备份 + 替换」时出现过 `assert old in s` 失败但文件已被替换的情况；
  涉及源码的变异/还原**一律用 Edit 工具**，并事后用 grep 计数核对（`grep -c` 关键行）。
- Edit 工具替换「表格某一行的开头单元格」会**整行吞掉**：往 markdown 表格追加行时，锚点要取上一行**结尾**
  （如 `归 P7。 |`），不要取下一行的开头。
- `LobbyServer` 的大包路径有语义盲点：`ws` 的 `maxPayload` 与 `LOBBY_TRANSPORT_MAX_MESSAGE_BYTES` 同为
  64 KiB，超限帧会被 `ws` 以 1009 关掉，`accept()` 里那段 `byteLength > maxMessageBytes → rejectBinary()`
  （1003）实际上够不到。P7 验大包时要先确认期望值到底是哪个码。
