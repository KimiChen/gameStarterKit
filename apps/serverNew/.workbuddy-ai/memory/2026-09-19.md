### 修掉的两个真实缺陷（同一类：`initialized` 是模块级状态，失败却发生在中间步骤）

1. `initializeServiceRuntime` 只在 `directNetwork` 分支回滚；多进程分支（`listen` 端点绑定失败、
   `forward` 路由装载失败）会留下 `initialized === true` 的半成品进程——旧通道可用、原生入口缺席、
   路由表可能已装载，重试被 `'service runtime already initialized'` 挡住，**真正的失败原因被掩盖**。
2. 角色校验（配置了原生入口却没有角色）发生在 `clientGateway` 建立之前，同样留下 `initialized === true`。

修法：`initialized = true` 仍在函数开头（保持「初始化期间即视为已初始化」以免并发关闭跳过清理），
但所有失败统一走 `rollbackServiceRuntimeStart()`；该函数额外做 `nativeLobbyProcessRoutes.reset()`——
残留 handler 的依赖（鉴权校验器、在线归属、连接）已释放，继续被跨进程请求命中就是静默执行。

### 关键坑

- **`nativeLobbyConfiguration` 的完整性校验先于端口冲突校验**：`NATIVE_LOBBY_PORT` 与旧通道端口相同这条
  失败用例必须把五个 `NATIVE_LOBBY_*`/`WEBPLATFORM_*` 变量**全部给全**，否则先报
  `native Lobby configuration is incomplete`。只给一个变量的场景要留给「配置不完整」那条用例。
- **端口被占是唯一能验证「路由表卸载」的失败形态**：装配顺序是「装载路由表 → 绑定端点」，
  配置类失败发生在装载之前，所以必须用真实 `net.createServer()` 占住一个空闲端口触发 `EADDRINUSE`。
- **两个对等用例缺一不可**：让 `forwardedContext` 虚构 `sessionEpoch`/`connectionId` 时，
  「同一组协议用例对等」用例**仍然通过**（handler 都不依赖连接级字段），只有探针用例咬得住。
  反过来让 uid 用 `String(internalUid)` 顶替时，对等用例首条就失败。这两个方向都验过。

  这样「幂等记录的键不含 connectionId」才是被验证的结论，而不是被复用同一个 context 掩盖掉。

### 联调踩到的三个坑（下次直接用）

1. **`guild.join` 的公会目录是硬编码 `GUILD_IDS = {1,2,3,4}`**，自造 guildId 会得到
   `INVALID_PAYLOAD「未知工会」`。真实库上公会成员/事件会跨运行累积，所以断言要取**前后差值**
   （「恰好 +1」）而不是「等于 1」——后者更脆弱也更弱。
2. **客户端 `collect` 不能丢弃不匹配的帧**：`guild.join` 的领域推送可能先于回包到达，
   丢弃会让「先到的推送」凭空消失、后续断言变假阴性。要收齐后按原序放回队首。
3. **两层独立防御会吃掉单层变异**（实测三层）：
   - 只撤公会「已是成员」守卫 → 13/13 **仍全绿**（通用闸的 `done` 短路直接返回缓存结果）；
   - 只撤通用闸的 `done` 短路 → **编译期**失败（`idempotency` 被收窄为可能 undefined），
     自检如实报「服务进程提前退出 code=1」而不是静默通过；
   - 两层同时撤 → **恰好只有那 2 条幂等相关场景**变红，其余 11 条保持绿。
   结论：断言「无重复副作用」时要意识到它由多层承担；单层变异为绿**不等于**断言不承重。

1. **旧通道重连必须先过 SDK `min uptime`（默认 5000ms）**：不过门槛就断，SDK 直接拒绝自动重连

   **已经为真**，`waitFor` 会立刻返回，随后的 RPC 正好撞在断线处理器上被判 `CONN_LOST`；而且那个
   `RpcError` 的 message 是**空串**（`RpcError(code, msg = "")`），只打印消息等于没有诊断。
   正确断言是「先等它离开 ready，再等它回来」。
3. **场景间必须把两条链都归零**：`WebSocketClient` 是单例、`configure` 又要求「切换前先释放」，
   任一场景中途失败而没走完 `leave()`，后续场景会全部变成同一条 `必须先释放当前连接` 的假失败，
   真实故障被噪音掩盖。

### 变异验证（证明断言承重）

  → **恰好** 3 个依赖显式端点的场景变红，其余 5 项保持绿。

  不以 `git diff` 作证据）；还原后受影响客户端网络测试 **54/54**。
