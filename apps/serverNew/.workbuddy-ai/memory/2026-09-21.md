**产物**：`apps/shared/schema/protocols/schema-v1.json`（协议声明**语言**真源）+

**六条要记的设计约束（改之前先读）**：

1. **语言即数据**：字段种类→允许的约束键、API/推送/声明的键集合、缺省值、上限全在 JSON 里，
   解析器按它判合法/非法 ⇒ 只改一处，⛔ 不存在第二份白名单。
2. **两道闸 = 语言闸 ∩ 实现闸**：各 `case` 自己声明「真的消费了哪些键」，末尾再校一次。
   语言里登记了但解析器没实现的键 ⇒ **拒绝**，⛔ 不是放过去然后静默忽略

6. **本层只管单文件规则**；跨文件/跨域（域名重复、路由全集、operation group 所有权、错误码聚合顺序、

## BF2：schema 生成 shared 协议（口径 A，已完成）

**做法**：14 个域全部迁入 `apps/shared/schema/protocols/C2S/*.json`；新增渲染器
`apps/server/tools/plugin-codegen/schemaDomainCodegen.ts` 生成 `domains/<域>.ts`；语言扩 `external` /
`nullable` / `pattern(+patternCode)` / `enumCode` / `sizeCode` / `check` / `assert` / 字段级 `readonly`；
域内复杂逻辑落在**非生成**的 `apps/shared/src/protocol/lobbyRpc/checks/<域>.ts`（6 个）+ `economy.ts`
（`validatePurchaseResult` 迁入）。`legacy/` 整目录删除。

**关键坑（跨项目通用）**：

- **`domains/<域>.ts` 字节 digest 闸 = 「改了字节必须同批 bump contractVersion」**。改 schema 会全变，
  **改渲染器模板也会全变** ⇒ 本次被迫 bump 两轮。加新约束/新渲染分支前先想清楚要不要一起 bump。
- **`writePluginArtifacts` 先写 `domains/*.ts`、后过 digest 闸** ⇒ 闸失败时磁盘停在「domains 新、
  registry 旧」的半写态。恢复方式就是 bump 后重跑 writer（`--check` 会给出同一句提示），别去手工改 registry。
- **生成物不能归插件所有**：把 `domains/**` 登记进 `protected-paths.json` 的 `generatedWriterOwned` 后，
  插件所有权里「域 descriptor 归插件」这条规则正面冲突（实测：移除登记 → plugin 套件 39/40 通过；
  加回 → 28 条红）。定论：**插件的域源改到 `schema/protocols/C2S/<域>.json`**，descriptor 不再归插件。
- **插件锁「规则演进」的处置**：工具只自动跳过「树上**已不存在**」的越权条目；树上仍存在的会被拒。
  错误信息原文即处置指引——「先用 `plugin -- check` 核对并修正锁」⇒ 手工删掉那一条，再
  `install --reinstall-from-tree`。
- **同仓迭代必须 bump version 才能 `reinstall-from-tree`** ⇒ 改包内文件（含包内测试）要**一次改完**再
  bump+重装，否则会连 bump 两次（本次 arenaShop 1.0.2 就是这么被吃掉的）。
- **`kit-import-boundary` 的 shared 归属**：`checks/<域>.ts` 必须与 `domains/<域>.ts` **同属主**，
  否则「用本 kit api 面校验自己的域」的既有形态集体变红。

**结果**：`apps/server` 全量 **1010 passing / 4 failing**（4 条全是 §9 #9 既有 income 端点基线）；
plugin-codegen + protocol-schema **69/69**；plugin 四件 **51/51**；两个 tsc exit 0；两个锁 ✔
