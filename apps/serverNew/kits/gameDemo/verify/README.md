# gameDemo 验证脚本

在仓库根执行 `node apps/serverNew/kits/gameDemo/verify/native-live.cjs`。
先在 serverNew/server 运行 `pnpm generate`。使用已有 bearjoylive 测试线路（Redis 9/8），
要求本地 Redis 6379/MySQL 3306 可用，端口 18090/28090 空闲。
脚本启动并回收真实单进程宿主，使用临时测试账号，不清空数据库。
不带参数验证状态查询及开发入口关闭时拒绝发放；加 `--assets` 验证一次性初始化、资产 sync、商店购买/重试、邮件已读/领取。
`routes.cjs` 由宿主全路由契约测试加载；新增路由须补齐该包场景，宿主仍检查每条本运行时路由实际被驱动过。
完整玩法与多进程故障验收脚本已提供；测试脚本不会自动清空或删除账号数据。

`--production` 包含资产链路并验证计时炼丹、英雄升级；加 `--restart` 在炼丹中强杀并恢复。
`--season` 包含 production，额外验证后台计分、开发提前结束、离线发奖与邮件领取；配合 `--restart` 再次中断活动结算并恢复。
隔离宿主可在自己的 bearjoylive 配置中指定临时 MySQL（本轮使用 3307）；不要改工作项目的现有账号或清空数据。

`--natural` 等待真实 10 分钟活动自然结束，离线期间仍发邮件，不改服务时间；包含 production 链路。
`--guild` 使用两个认证账号验证创建、邀请、接受/重试、离开与盟主转交。

`--boss` 调用 `boss-live.cjs`：三个真实账号分别攻击三个房间，独立读 Redis，强杀整个单服并重连，验证原局/HP/伤害/阶段、租约代次、旧攻击重放、继续攻击与房间推送。多 worker 与结算中断另做验证，不由此脚本的单进程结果代替。
