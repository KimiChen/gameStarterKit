# 独立配套系统：监控、部署与运营

> 目标设计，尚需实现与验收；不是当前仓库的完成清单。返回 [最小框架入口](README.md)。

## 为最小核心提供能力，而不进入玩家请求进程

本页对应 G1、G6、G7。**上线必要性、是否独立进程、是否需要自建平台是三件事。** 基础监控与备份可以必须具备，同时通过成熟外部工具实现；不要求自建监控产品，也不要求拆成许多微服务。

| 配套系统 | 独立运行的工作 | 游戏进程中的薄接口／适配 | 不可用时的边界 |
|---|---|---|---|
| 监控、日志、告警 | 采集器、日志索引、历史指标、阈值判断、通知和值班 | 脱敏结构化日志、关联编号、轻量计数／耗时、就绪信息 | 有界缓冲、批量与采样；普通遥测可丢弃并计数，不拖住请求或填满磁盘；关键权益审计仍可靠保存 |
| 发布与进程管理 | CI 构建、分发产物、启动停止、重启退避、滚动发布 | 固定版本启动、就绪／排空、当前配置版本与在途数量 | 控制平台停机时，已运行实例继续服务；新发布暂停；已有独立托管是否继续重启需单独验证 |
| 运营与客服 | 员工登录、页面、审批、查询汇总、工单和批处理 | 受限查询、封禁／补偿等明确领域命令、操作状态查询 | 后台不可用时玩家继续正常操作；未完成管理任务有凭据可接续，不在前台请求里等待后台 |
| 配置与活动发布 | 编辑、导入、验证、差异预览、发布与版本存储 | 启动时校验配置；使用只读快照，报告已生效版本 | 已运行实例在声明有效期内使用最近有效版本；无有效版本不得就绪；紧急撤销类规则单独设收敛时限 |
| 身份与区服管理 | 平台登录换证、账号绑定找回、目录发布、开服迁服编排 | 校验会话有效性、角色归属、封禁及目标区服 | 身份验证可能是必要在线依赖；到期或无法有效验证时拒绝相关操作，不为“外围独立”绕过授权 |
| 权限与密钥 | 员工权限管理、服务身份、密钥发放撤销 | 每次命令校验身份／范围／有效期，按职责使用最小存储权限 | 权限失效拒绝写入；不能仅凭内网地址信任调用方，也不能永久缓存撤销前权限 |
| 备份与修复 | 存储备份、异地副本、隔离恢复、核账工具和审批 | 维护／停写协作、按版本查证、受控领域修复命令 | 正常请求通常不等待备份；备份失效触发处置时限；恢复属于存储维护流程，不开放远程任意改库 |
| 报表与分析 | 事件采集、聚合、报表、数据导出和成本分析 | 提供有定义的业务事件／受限读取；必要可靠事件绑定提交 | 统计延迟不改变真实余额；持久业务事件与可丢遥测分别定义，报表不能用于确认发货 |

关键审计与业务效果按设计原子记录，外部汇总失败可后续交付；如果某项强制审计连本地权威存储都无法保存，相关敏感操作应失败或停留处理中，不能当作普通日志直接丢弃。

## 接口数据与受控命令分别设计

以下是目标契约类别，不是当前已存在的 URL 或函数名。具体 API 从共用定义派生，内部管理契约与客户端可见契约分开发布。

| 接口类别 | 最小信息／行为 | 权限和资源限制 |
|---|---|---|
| 存活、就绪、版本 | 是否能运行、是否可接工作、程序／配置／契约版本、明确失败原因 | 区分存活与依赖就绪；避免共享存储故障造成所有实例无限重启；限制探测频率，缓存有时限的探测结果 |
| 日志与指标 | 时间、角色、区服、实例、功能、阶段、稳定错误码；计数和耗时 | 不暴露凭证、全量玩家数据；禁止以玩家 ID 作为无限增长的指标标签；限定输出大小和抓取开销 |
| 业务结果查询 | 操作编号、所属角色、处理中／完成／失败／待查、结果版本 | 校验可见范围，分页和限量；复杂跨表汇总由外部查询服务或读模型承担，不做全库扫描 |
| 管理业务命令 | 动作、对象范围、稳定操作编号、预期版本、原因和执行结果 | 校验服务身份、操作者授权与区服范围；绑定参数、去重、权限和审计，禁止任意代码或 SQL 执行 |
| 生命周期控制 | 请求排空、查看排空进度、当前就绪状态 | 仅允许部署身份；可重试、有期限；操作系统启停由外部托管处理，游戏进程不拿 SSH／集群管理员凭证 |
| 业务事件交付 | 事件编号、版本、发生时间、最小业务事实、必要关联编号 | 关键交付走持久凭据与去重；接收端做版本兼容，不将网络发送成功视为业务完成 |

部署控制器调用生命周期接口，监控使用观察接口，后台使用领域命令；它们都不直接读取游戏进程的内部对象。外部日志采集器或数据库备份工具可通过宿主／数据库专用接口工作，不必让游戏进程中转所有数据。

## 可执行的拆分要求

| 检查 | 通过条件 |
|---|---|
| 代码依赖 | 核心只能依赖契约、最小适配器和所选模块；不能反向 import 后台服务器、监控后端或部署工具包 |
| 启动行为 | 未配置监控平台／后台／AI 服务时仍能启动有效的最小业务环境；身份、有效配置和权威存储等必要依赖缺失应清楚报错 |
| 运行隔离 | 外围 CPU／内存／磁盘压力有独立限额；重启后台不重启游戏；可共享主机，但需测共同故障影响 |
| 发布隔离 | 外围可按兼容契约单独升级；新旧接口并存窗口和停用条件明确，不要求玩家服务跟随每次后台 UI 发布 |
| 故障注入 | 停日志接收器、后台和配置发布服务，验证资源有界与普通业务语义；再单独验证身份、存储故障的拒绝／恢复行为 |

### 02．账号、登录与会话

知道玩家是谁，并且让登录、退出、封禁都能真正生效。

参考方向：账号管理与会话入口参考 Alloy；凭证撤销和失效处理吸收 gameKit 的约束。生产身份服务继续通过 HTTP 契约接入。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 02.01 | 平台登录 | 验证微信等平台提供的登录证明，不能只凭玩家传来的账号编号放行。 | 基础 |
| 02.02 | 账号与角色分离 | 一个账号可以在不同区服创建不同角色；区分登录身份与角色存档。 | 按需 |
| 02.03 | 登录有效期 | 登录凭证到期或被撤销后，提示重新登录，不能继续操作。 | 基础 |
| 02.04 | 多端登录规则 | 明确新设备登录后是踢掉旧连接，还是允许多个设备，并保证不会互相覆盖存档。 | 基础 |
| 02.05 | 账号限制 | 支持封号、解封、临时限制和强制下线，并说明原因与期限。 | 基础 |
| 02.06 | 账号绑定与找回 | 需要跨平台或游客转正式账号时，验证归属后迁移，避免绑定错人。 | 按需 |
| 02.07 | 异常登录记录 | 记录登录失败和异常地点等必要信息，便于排查盗号；敏感信息按权限查看。 | 运营 |

### 03．区服与入口管理

让玩家进对服务器，让运营能安全地开服、维护和合服。

参考方向：参考 Alloy 的固定区服配置与入口组织，借鉴 eerie 的区服运营流程；跨服和合服另行建设验收。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 03.01 | 服务器目录 | 展示服名、开放时间、繁忙程度和维护状态；单服游戏也有明确入口。 | 基础 |
| 03.02 | 访问与维护规则 | 维护期间限制新玩家进入，测试人员可按白名单进入验证。 | 基础 |
| 03.03 | 区服数据隔离 | 同一个玩家在不同区服的数据有明确归属，不能串服读取或扣款。 | 按需 |
| 03.04 | 新服建立 | 按模板准备服务和数据，再经检查后开放注册，避免手工漏步骤。 | 按需 |
| 03.05 | 推荐与最近登录 | 帮助玩家找到合适的新服或已有角色，不必每次翻完整列表。 | 按需 |
| 03.06 | 跨服归属 | 跨服活动明确由谁处理、数据放哪里、故障后谁接手。 | 扩展 |
| 03.07 | 合服与迁服 | 处理重名、排行、公会、订单和角色归属，迁移前可预演并准备恢复方案。 | 扩展 |

### 20．配置、数值与活动发布

让策划和运营安全调整内容，不靠直接改线上数据库。

参考方向：参考 Alloy 的配置及模块组织，借鉴 eerie 的多环境发布流程，补齐检查和回退。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 20.01 | 配置统一定义 | 明确每个配置项的类型、范围和业务含义。 | 基础 |
| 20.02 | 策划表导入 | 导入数值表后检查错误编号、缺失引用和不合理数值。 | 按需 |
| 20.03 | 发布前差异预览 | 清楚展示改了哪些商品价格、奖励或时间，避免误发。 | 运营 |
| 20.04 | 配置版本绑定 | 记录一次购买或对局使用的配置版本，事后可以复核。 | 基础 |
| 20.05 | 测试与正式隔离 | 测试改价和生产配置互不影响，正式发布需要选择正确环境。 | 基础 |
| 20.06 | 小范围生效 | 先给测试账号或少量区服使用，再逐步推广。 | 运营 |

| 20.08 | 活动排期与冲突检查 | 安排开放范围、时间和领奖期限，检查重复或互相冲突的安排。 | 按需 |

### 22．运营、客服与管理后台

让运营处理日常事务，客服回答玩家问题，不必直接操作数据库。

参考方向：参考 Alloy 的 Adjust/GM 与后台组织，借鉴 eerie 的运营流程，所有写操作接入统一安全提交与审计。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 22.01 | 玩家综合查询 | 按角色或订单查登录、档案、余额和处理中的任务，按权限展示。 | 基础 |
| 22.02 | 封禁、解封和下线 | 由授权人员操作，限制范围和期限，通知玩家并记录原因。 | 基础 |
| 22.03 | 订单与道具申诉 | 把流水、订单及道具记录关联起来，解释为什么未到账或被消耗。 | 按需 |
| 22.04 | 补偿与邮件发送 | 选择对象、奖励和原因，先预览影响人数，再通过正式发放入口执行。 | 按需 |
| 22.05 | 维护及功能开关 | 安排维护、调整开放范围或暂停故障功能，查看是否真正生效。 | 基础 |
| 22.06 | 任务与失败单处理 | 查看未完成交付和失败任务，按权限重试或转人工调查。 | 按需 |
| 22.07 | 批量操作 | 分批执行并显示进度，可停止后续批次，不能一次卡住全服。 | 运营 |
| 22.08 | 客服处理记录 | 把证据、处理人、处理理由和结果留在一张工单中。 | 运营 |
| 22.09 | 测试工具隔离 | 模拟账号、改时间和开发调试只在明确授权环境开放。 | 基础 |

### 23．权限、安全与隐私

让有权限的人做正确的事，并控制账号和敏感信息风险。

参考方向：后台权限与访问审计参考 Alloy，结合三者的身份校验经验补齐统一治理；实际权限覆盖范围仍需逐项验收。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 23.01 | 后台身份认证 | 后台员工使用可撤销的身份登录，不共享一个永久密码。 | 基础 |
| 23.02 | 按角色和范围授权 | 客服可查单、运营可发公告、财务可退款；权限还要限定区服和数据范围。 | 基础 |
| 23.03 | 敏感操作复核 | 大额补偿、批量删档等操作要求明确确认；必要时由另一人复核。 | 按需 |
| 23.04 | 操作审计 | 记录谁在何时因为什么改了什么，并限制审计记录的修改权限。 | 基础 |
| 23.05 | 凭证与密钥管理 | 数据库密码和支付密钥由受控配置注入，可更新或撤销，不放进玩家数据或日志。 | 基础 |
| 23.06 | 隐私保护 | 只收集所需数据，展示时遮盖敏感内容，按规定保留、导出或删除。 | 基础 |
| 23.07 | 反滥用和账号风控 | 限制异常注册、刷接口和恶意重复领取；复杂设备关联分析按需要启用。 | 按需 |
| 23.08 | 内部接口保护 | 内部服务也要确认调用者和权限，不能因为在内网就任意修改玩家数据。 | 基础 |
| 23.09 | 区域合规接入 | 按发行地区及平台要求接入实名、未成年人保护等能力；适用时属于上线前置条件。 | 按需 |

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 24.01 | 结构化运行日志 | 统一记录时间、区服、功能和错误，支持搜索，敏感内容要脱敏。 | 基础 |
| 24.02 | 请求关联查询 | 把一次玩家操作经过的入口、存储和后台任务串起来查。 | 基础 |
| 24.03 | 服务指标 | 查看在线人数、失败率、响应时间、机器内存及数据库连接占用。 | 基础 |
| 24.04 | 健康和就绪检查 | 区分进程还活着与已经能处理业务，发布系统只把流量交给准备好的服务。 | 基础 |
| 24.05 | 业务异常监控 | 除了看机器，也看付费未发货、奖励积压或异常材料增减。 | 按需 |
| 24.06 | 告警分级 | 严重故障立即通知值班人，重复告警合并，恢复后也给通知。 | 基础 |
| 24.07 | 值班处理说明 | 每类关键告警有负责人、检查步骤、止损方式和升级联系人。 | 基础 |
| 24.08 | 日志保留与费用 | 按重要性决定保留多久和采样比例，避免无限增长或过早删证据。 | 运营 |

### 25．构建、部署、发布与回退

能够安全把新版本放到线上，出问题时有明确退路。

参考方向：参考 Alloy 的制品和进程控制，借鉴 eerie 的部署计划与托管方式；结合 gameKit 的幂等和交付凭据，补崩溃后初始化、查证在途操作、接续任务及客户端补齐，并验收排空、灰度和回退。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 25.01 | 固定发布产物 | 给每次发布确定版本和校验值，测试与正式使用同一份产物。 | 基础 |
| 25.02 | 发布计划预览 | 发布前列出目标环境、服务、配置和数据变更，避免发错区服。 | 基础 |
| 25.03 | 环境与配置校验 | 检查密钥、数据库和依赖是否准备好，缺条件时不开放服务。 | 基础 |
| 25.04 | 进程托管 | 独立托管各类服务进程，异常退出后自动拉起；初始化和依赖就绪后再接流量，连续失败需限制重启频率并告警。 | 基础 |
| 25.05 | 维护排空 | 停止接新连接或任务，撤销实例路由，再等待在途操作完成或交接；未结束房间按约定等待结束、迁移或中断，不直接强制销毁。 | 基础 |
| 25.06 | 灰度发布 | 先在小范围验证新版本，观察指标后继续扩大范围。 | 运营 |
| 25.07 | 回退方案 | 明确代码能退到哪一版、数据是否兼容；回退程序不等于自动撤销已经完成的交易。 | 基础 |
| 25.08 | 发布后验收 | 检查登录、同步及关键业务，失败自动停止后续发布并提示处理。 | 基础 |
| 25.09 | 依赖安全检查 | 检查依赖漏洞和产物来源，按风险处理，避免发布未经确认的包。 | 运营 |
| 25.10 | 崩溃重启与业务恢复 | 业务进程崩溃后重新初始化并加载已提交数据；查证在途操作、接续可靠任务、恢复客户端连接与同步，失败反复发生时进入告警处理。 | 基础 |

<a id="m27"></a>

### 27．备份、恢复与数据修复

不只会保存，还要在事故发生后找回数据并证明找回得正确。

参考方向：恢复保障参考 gameKit 的档案版本及冷档思路、eerie 的备份恢复工具；操作入口结合 Alloy 的模块组织，恢复正确性必须通过演练确认。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 27.01 | 定期备份 | 按数据重要性安排频率，数据库、关键热档及必要配置都有覆盖。 | 基础 |
| 27.02 | 异地及受保护副本 | 备份不只放在同一台机器，限制删除权限并保护敏感内容。 | 基础 |
| 27.03 | 恢复目标 | 事先约定可以接受的数据损失时间和服务恢复时间。 | 基础 |
| 27.04 | 真实恢复演练 | 定期在隔离环境恢复并核对余额、道具和未完成订单，不能只检查备份文件存在。 | 基础 |
| 27.05 | 恢复新旧数据判断 | 热档、冷档和备份同时存在时，依据版本判断，不盲目选文件时间最新的一份。 | 按需 |
| 27.06 | 修复预演 | 先显示将修改的账号、字段和原因，确认后再执行。 | 运营 |
| 27.07 | 修复记录与回退 | 保存修改前后内容和执行人；涉及货币时走调整流水，不直接篡改历史记录。 | 运营 |
| 27.08 | 修复后的补处理 | 恢复后继续处理未完成交付，同时避免重复发奖或重复扣款。 | 按需 |

<a id="m30"></a>

### 30．数据分析与经营报表

帮助团队理解玩家体验和经营情况，和业务真账本分清职责。

参考方向：参考 Alloy telemetry 的事件组织，借鉴 eerie 的统计及数据查询入口，统一指标口径与权限。

| 编号 | 子功能 | 业务描述：具体要做到什么 | 建设标记 |
|---|---|---|---|
| 30.01 | 事件定义 | 统一登录、完成任务、购买等事件的名字和含义，避免不同模块重复统计。 | 按需 |
| 30.02 | 可靠采集与去重 | 网络重试不能把一次购买统计成两次，采集失败不阻塞玩家正常操作。 | 按需 |
| 30.03 | 运营指标 | 查看活跃、留存、流失和关键流程完成情况，指标口径写清楚。 | 按需 |
| 30.04 | 经济异常分析 | 检查货币产出、消耗和异常增长，为数值调整提供依据。 | 按需 |
| 30.05 | 渠道与区服分析 | 按发行渠道和区服对比效果，同时遵守隐私和访问范围要求。 | 扩展 |
| 30.06 | 账目与报表分工 | 经营报表可有延迟；退款和发货仍依据订单、钱包及交付记录，不能以统计报表做账。 | 基础 |
| 30.07 | 数据保留与导出 | 限定谁能导出哪些数据、保存多久，导出过程可追踪。 | 运营 |


## 一次发布如何协作

| 顺序 | 谁负责 | 具体行为 | 放行条件 |
|---|---|---|---|
| 1 | 测试与质量 | 检查规则、协议、旧档及关键链路 | 无阻断项，未覆盖风险已说明 |
| 2 | 配置＋部署 | 预览将修改的服务、版本和数据 | 目标正确，依赖及凭证齐备 |
| 3 | 备份恢复 | 准备适用的恢复点及迁移方案 | 确认恢复方案能执行 |
| 4 | 维护排空＋部署 | 少量实例先停止接新操作，收尾后更新 | 在途操作和未结束对局按规则处理 |
| 5 | 监控＋验收 | 检查能否正常登录、同步和执行关键操作 | 就绪检查及业务指标正常 |
| 6 | 发布控制 | 扩大发布或停止并按方案回退 | 旧数据与目标程序兼容，不能盲目回退 |
